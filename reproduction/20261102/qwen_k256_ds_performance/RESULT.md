# Qwen3-VL 8B EADP K256 DeepStack 性能实测（2026-11-02）

在本机一张 NVIDIA A40 上，同一个 Qwen3-VL-8B BF16、FlashAttention 2、作者 EADP α=0.5/β=2 的实际 K256 视觉位置、相同提示词下，比较 DeepStack 关闭与开启。16 个 DocVQA 固定问题，每种模式两臂各一次测量（64 次实际测量），每种模式两臂先各预热一次。样本内交替安排开启/关闭顺序；不是全量数据，也没有跨机器或多次重复。本次不读 GT、不评分。

| 测量 | 关闭 | 开启 | 开启减关闭 |
|---|---:|---:|---:|
| 固定输出 32 token，总时间均值 | 1.873364 秒/题 | 1.877397 秒/题 | +0.004033 秒，+0.215% |
| 固定输出 32 token，总时间中位数 | 1.869946 秒/题 | 1.871722 秒/题 | 配对差中位数 +0.004495 秒 |
| 固定 32，首轮语言模型 CUDA 事件均值 | 78.890 毫秒 | 80.474 毫秒 | +1.584 毫秒，+2.007% |
| 固定 32，首轮 CUDA 事件中位数 | 78.736 毫秒 | 80.413 毫秒 | 配对差中位数 +1.714 毫秒 |
| 全程 PyTorch 已分配显存峰值，16 题均值 | 16932.291 MiB | 16932.291 MiB | 配对均值和中位数均 0 MiB |
| 全程 PyTorch 已分配显存峰值，16 题最大值 | 16932.383 MiB | 16932.383 MiB | 最大值相同 |

自然结束测量（原 max_new_tokens=2048，不强制输出长度）：关闭/开启平均 0.681384/0.670067 秒，中位数 0.581731/0.607433 秒。16 题中 10 题 token 数改变，关闭/开启平均 7.125/6.875 token；两臂均 16/16 EOS、0/16 达 2048，11/16 回答文字改变。长度改变影响耗时，因此不据此声称开启可以加速。固定32时以 min=max=32 迫使两臂输出同样长度，与真实自然终止不同。

每次总时间以 `torch.cuda.synchronize` 前后包住：包括图片读取、预处理、视觉塔、作者真实选择、语言模型生成、解码及两臂均有的轻量观测钩子，不包含模型加载和结果校验/保存。首轮指标为 CUDA 事件，覆盖开侧选取并注入 DeepStack 的相关工作及语言模型首轮 forward，不是整个模型 prefilling 或全程耗时。显存是 reset 后 `torch.cuda.max_memory_allocated`、包含常驻模型的本次推理峰值，并非 nvidia-smi 全设备峰值，也不包含 PyTorch 分配器外的所有显存；整次峰值相同不能推出 DeepStack 没有额外中间内存，额外开销可能没有超过整次推理的其他峰值。此处读数精度不能拿来证明更广泛设置下的显存消耗为零。

64 次实际作者有序选择与已复核固定16数据逐项相同；自然结束的32条输出 token 序列也与此前开/关实验逐条相同。所有图片和作者源码经过运行前 SHA 校验，版本、模型路径、实际设置见 `runtime.json`；原逐次测量含 token ID、时间、峰值见 `observations.jsonl`，聚合数据见 `summary.json`。计时代码 `benchmark.py`、可追溯容器命令 `launch.json` 和终端退出 `terminal_proof.json` 均保留。任务在同一设备/16短文档/单次测量的局限下，整体速度差小于单题波动，不宜外推成精确普适百分比。
