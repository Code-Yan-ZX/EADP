# Posthoc selector-geometry routing diagnostic

Test three unlabeled, predetermined rules after observing the existing DEV aggregates, random baseline and earlier unsuccessful simple-image heuristics. The experiment is posthoc exploration; no evaluation answer is used to fit a model, choose a rule, select a threshold, or filter questions. Report all rules for all tasks, not just a favorable one. Do not access CONFIRM or FINAL labels or inputs.

Use the formally and independently accepted E4 DEV K128/DS-on natural records, including their full P3 positions, 128 selected spatial indices and accepted processor identity; no model run is added. The existing JSONL record also contains generated answer fields: extraction necessarily parses these already accepted prediction records but uses only input/position/selection identity and never reads labels or score files. Before feature extraction, validate record file, E4 acceptance, independent review, source identities and all 384 question/group IDs against accepted E1 inputs. Reject duplicate/missing arms, non-unique 128 indices or coordinates inconsistent with the 1,024 original image positions. Determine actual image token x/y grid from the two recorded P3 axes rather than assuming a square grid; normalize x and y using minima and maxima of all 1,024 original positions, and use the corresponding selected positions.

For every image compute: (1) the mean Euclidean distance to the nearest other selected coordinate after x/y normalization; (2) the number of occupied cells in an 8×8 grid obtained by mapping each selected integer coordinate to `floor((coordinate-min)*8/(max-min+1))`; and (3) Shannon base-2 entropy of occupancy frequencies in a 4×4 grid defined analogously. All 128 coordinates must be distinct, with positive coordinate extent in both axes. Fixed rules: assign K512 to the 42 images with the *smallest* nearest-neighbor distance, the 42 with the *largest* 8×8 occupancy, and the 42 with the *largest* 4×4 entropy, respectively; assign K128 to the other 86. Break ties with ascending SHA256 of UTF-8 `20261105|{group_id}`. This yields 42×512+86×128=32,512 tokens, mean K254, per task, versus fixed K256 total 32,768. Also reproduce three fixed random allocation controls using `20261105|random|{seed}|{group_id}` for seed 0/1/2; report all seed results. Rules use the entire task batch and hence are not online deployment policies.

Extract and hash the complete feature table before parsing any score values; score file bytes were hashed as a source identity during initial freeze, but no score values were inspected. Source records already contain and therefore expose accepted predicted answer fields on JSON parsing, but the extractor must only access the fixed fields above. Only after a frozen feature file and independent source/feature verification pass, join the already accepted E4 DEV `K128-D1`, `K256-D1`, `K512-D1` scores by task/qid/group. Report mean score, difference from K256 in percentage points and image-level improved/declined/unchanged for all six rules, all tasks and all 128 questions; preserve all answers and denominators. The fixed rank rules and already observed DEV results make this exploratory, not a test of significance or learned router generalization.

Token count is not actual compute or latency. Geometry is computed from an existing K128 selector pass; an online implementation would need that pass and could need a second K512 generation, so this offline reuse is not a measured budget, end-to-end speedup or equal-compute comparison. No selector cost is ignored in any eventual deployability claim. Stop if any required source, metadata, geometry or score identity fails; retain failures and do not select subsets.
