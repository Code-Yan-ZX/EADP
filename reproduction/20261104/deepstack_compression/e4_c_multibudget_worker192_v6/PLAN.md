# 192-image multi-budget timing: v3 execution candidate

This exploratory expansion uses the previously frozen 192 measured identities (64 per task), plus 30 distinct pilot warmup identities, with 7,680 measured and 240 warmup jobs. All four budgets, the natural and fixed32 protocols, and five repeats per measured image are predetermined in proposal002. It uses the already reviewed v3 real-model timing primitive: the first-token boundary is synchronized after first-token selection, and generation completion is synchronized before text decoding or the raw-output fsync. Fixed32 is 32 emitted tokens with 31 subsequent decode steps; this is not end-to-end user latency.

The no-GPU worker preflight uses the accepted E1/E4 inputs and 888 historical natural endpoints, actually processes all 222 identities, hashes four weight payloads, imports the real model implementation and checks the image/processor identities without constructing the model or initializing CUDA. It does not touch the new 888 fixed32 outputs. Previously accepted E1/E4 DEV mixed prediction records are opened and parsed for identity only; no GT or scores are opened. An independent CPU source review must finish before this bounded, supervised, retained-container preflight can start.

The GPU launcher and worker use a separate source-pinned gate. GPU authorization requires its not-yet-created GPU plan, v3 real CPU-container evidence and independent review, all 888 new fixed32 references with formal and independent complete reviews and clean exits, the formal verification prelaunch review, frozen analysis and background-monitor source reviews, a live background observer whose recorded monotonic start and fixed duration cover the full eight-hour GPU hard limit plus twenty minutes of cleanup, and a separate GPU prelaunch review. Each missing item rejects before execution. The root coordinator alone schedules GPU work. Time limit, progress stall, disk, exclusive GPU, full user deadline including acceptance reserve, retained-container stop/kill/inspect and process supervision are enforced. A proposal, CPU test or preflight cannot authorize the GPU.

On the real path, every generated token sequence is fsynced before endpoint validation, then each completed record is checked against the exact same image/budget/protocol reference; a mismatch preserves the failure and aborts. The worker records actual processor checks and weight identity before the model, and rechecks source, weight stats and reference identity after all jobs. Event output uses the frozen complete order, including failures; partial timing must not be summarized. Full high-dimensional tensors and KV bytes are not reconstructable from the summaries. Prior-source identity work opens and parses previously accepted E1/E4 mixed predictions; no GT or scores are read. Later analysis must retain all 7,920 jobs, include all observer and supervisor windows, and label unknown interference rather than drop measurements.

Future formal proof: `e4_c_multibudget_worker192_v6_accept/verification001.json`, `monitor_verify001`; separate independent proof: `e1_independent_review/e4c_multibudget_worker192_v6_result_review.json`, `review_e4c_multibudget_worker192_v6_result.py`, `monitor_e4c_multibudget_worker192_v6_result`.
