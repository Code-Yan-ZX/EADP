# 两个后验、无答案训练的对照建议

2026-11-05。建议按先后顺序考虑；均为已经看过同一 DEV 成绩后的**探索**，不是确认性验证，也不使用答案训练、调参或选择样本。三天时限的当前剩余约两天；以下上限是待主控在启动时按真实时钟、显存、重 I/O 和已有队列复核的资源上限，并非实测用时或已获运行授权。生成完整且无 GT 的正式与独立验收均通过后，才允许按事先固定口径读取新 DEV 答案评分；中途不按题目表现选择或替换样本。

## 现有证据与限制

- 本轮已双验 E4（每任务 128 图）：K256 D1 的 Doc/Text/AI 为 67.85/80.78/82.03；同题三固定 seed 的随机 K256 均值为 55.43/73.05/73.96。随机不是免费速度基线：现有实现先执行作者 greedy 再丢弃结果。见 `../e4_analysis/score_panel003/RESULT.md` 和 `../e6/random_full_analysis_v3/RESULT.md`。
- Pixel τ=0.2 的 Doc/Text/AI 为 91.50/82.34/81.25，但其 K 中位数为 480/528/385.5，不能与固定 K256 称为等算力；τ=0.45 相对 τ=0.2 的文本任务损失明显，τ=0.1、0.2相对 τ=0 的非劣证据均不足。见 `../e6/pixelprune_t020_dev384_analysis/score001/RESULT.md`、`../e6/pixel_t020_t045_comparison/RESULT.md`。
- 既定几何 6 条规则在均值约 K254 的离线拼接下未超过同题固定 K256；规则需要批排序和潜在二次生成，并未证明所有自适应策略失败。384 图的八个流特征与 K512−K128 分数差相关总体弱且跨任务方向不一致，不能据此用 DEV 选一个 router 或阈值。见 `../e4_adaptive_geometry_v2/RESULT.md`、`../e4_multistream_expansion343_analysis/RESULT.md`。
- Pixel NVML 仅三个锚、每臂一次，包含图形背景和采样漏峰；EADP 192 图 TTFT 是另一次、不同实现和背景的测量，不能直接组合为公平速度比较。见 `../e6/pixel_wavefront_t020_nvml_execution_analysis/RESULT.md`、`../e4_c_multibudget_analysis192_exec/RESULT.md`。
- 当前 Git `exp/m14-facility-lossless-accel` 的较新 M12 记录在另一环境/样本中已见直接降低分辨率优于多种 pre-ViT 稀疏启发式，但其设置和评分口径不能与本轮 384 题直接拼表；M13 报告存在尚未填充的表格，不当作已完成的深度结论。见 `/media/disk2/YZX/research/EADP/reports/m12_retinagate_falsification.md` 与 `m13_hierarchy_compression_oracle.md`。

## 1. 优先：同 384 输入的真实 K256 降分辨率基线

**问题。** 在本轮作者环境和同一数据上，把图像实际缩放到 processor 最终产生 K=256 的网格，是否已在质量上接近或超过 1024 输入后选择 K256 的 EADP？这直接检验已有 Pixel 质量优势是否只是因为它保留远多于 256 的 token，并补充早先不同环境的 R-res 强基线。

**设计。** 沿用已验 E1 的 384 个 `(task,qid,group,image,message)`，每任务 128 图。固定一个确定性 processor 配方：例如对当前固定正方形预处理尝试 512×512，先在三任务各一张实际验证 merged grid **确实恰为 256**；若模型的真实 resize/rounding 导致不是 256，则在任何质量生成前固定一个适配该 processor 的确定规则并重新预检，不把近似 K 宣称为精确 K。保留作者自然贪心 recipe、EOS、相同权重/后端与 DeepStack-on；原始低分辨率条件的 mRoPE 随真实网格计算，不能强塞全分辨率 P3。新生成一个低分辨率臂（384 次）；主对照是既验同题 E4 K256 D1，次对照同题 random 三 seed 均分与 E4 K512/K1024，Pixel 各阈值只作为明确动态 K 的参考。所有任务和配对差、bootstrap 区间、EOS/空答/截断、实际网格和每题均保留；只在双验收后用同一作者与独立口径计分。

**预先固定的可证伪读法。** 先声明相对 EADP K256 每任务的非劣余量为 −2.0 百分点、图像组配对 bootstrap 10,000 次（每任务各128图）。若任一任务的差值 95% 区间下界低于 −2.0，不能称该任务达到该探索性非劣目标；若区间连点估计方向都不稳定，结果保持未决。三个任务全部报告，区间未做多重校正，且选题/余量发生在已观察 DEV 之后，不能称验证或跨分布泛化。R-res 高于 EADP 的点估计也不能自动宣称视觉 token pruning 的普遍无效。

**成本与执行门。** 先做 CPU 真实处理器/网格及 K=1024 keep-all 控制，再三锚真实模型身份 smoke；随后才一模型/384 图自然生成。旧 Pixel 作者版 384 题约 275.5 s 只是不同实现的粗略量级，不能作为新臂预测；建议在固定执行链与监督后为生成单独预留不超过 3 h 的保守外限、至少 10 GiB 数据盘余量及单独验收/评分时间，依据首个完整 smoke 和剩余截止修订并留痕。此臂不是时延测量；如质量值得继续，再另做与 EADP 随机配对、同输入、模型隔离的 TTFT 和独立峰值显存，而不是从已有不同日结果相减。

**先例。** 图片缩放是已知强基线，不是新方法；[Foveated Compression](https://arxiv.org/abs/2610.07729) 直接将压缩表示与等 token 下采样比较，[VisionThink](https://proceedings.neurips.cc/paper_files/paper/2025/file/88be023075a5a3ff3dc3b5d26623fa22-Paper-Conference.pdf) 也讨论了按图调整分辨率。本提案用的是固定输入、无学习 R-res，不复现这些方法的训练或自适应机制。

## 2. 可选机制对照：固定相同 mask，比较 ViT 前后删除

**问题。** 同一组保留位置，早删产生的质量变化有多大？这把“选了哪些位置”和“保留位置能看到多少视觉上下文”拆开；不是先找更花哨的 scorer。M12 已对 variance 等像素启发式给出负证据，因此不把它们重命名为新方法。

**设计。** 事先按输入身份哈希、与答案和模型输出无关的固定顺序，每任务取 32 张、总计 96 张；任务选择发生在 DEV 结果已被观察之后，只作机制诊断。在每张图的两个 mask 家族内保持 K=256、相同原空间索引和顺序：① 已验 EADP K256 索引；② 先固定随机 seed 20261104 的同题已验随机索引。分别对每个 mask 比较 **完整 ViT 后 gather** 与 **完整图网格构造位置后、ViT blocks 前按同一 2×2 merge-group 删除**。在两路径上维持同一语言 prompt、生成 recipe、P3 原坐标和三路 DS 行映射；实际记录索引、main/三路 DS、首 prefill、位置/cache、自然输出与终止状态。参考原文 EADP/随机 post 的输出可作为验收对照；如同环境复现不一致，则应在同一新环境重跑成对 post 对照并披露版本/数值差异，不能把差异直接归因于删除时机。

EADP 的 mask 来自完整视觉塔，本实验是**昂贵的离线 oracle 干预**：它绝不能被报成提前剪枝的可部署速度，也不能忽略为获得 mask 而花费的完整前向。随机同 mask 是控制；一个 seed 的机制效应不能概括所有随机性。三锚必须先通过 keep-all、位置/DS 对齐及对原已验同臂输出/选点的真实 identity，任何真实后端版本改变都要重验。尽可能使用原路径 `Qwen_vl/model/retinagate.py` 的 merge-group 稀疏语义，但其现有 SDPA/transformers 环境不同于本轮作者环境，迁移不可视为已验证；若无法闭合身份则停止此方案。

**预先固定的可证伪读法。** 主比较按任务和 mask 家族分别报告 `pre−post` 配对差、95% 图组 bootstrap 与全部 rescue/break；再报告两个 mask 家族间差异的配对交互。若 EADP mask 的 `pre−post` 95% 区间上界低于 −2.0 pp，则支持该任务在固定 mask 下“提前删除损失至少 2 pp”的限定假设；若区间跨越阈值则未决，不能据此认定无上下文损失。重复的显著性、交互和阈值均为后验 DEV 探索，不作多重比较后的确认结论。若两路径自然输出或输入身份失败，应完整保留失败，不用其他图替换。

**成本与先例。** 基础 96×2 新 pre 臂，必要时追加 96×2 同环境 post 控制；三锚后估算真实开销，建议各阶段独立设最多 3 h 硬上限并给验收留时间。PixelPrune 本身已经是预测编码的输入侧删除（[论文](https://arxiv.org/abs/2604.00886)），[VScan](https://arxiv.org/abs/2505.22654) 等也已研究不同阶段的视觉 token 缩减；本对照不以“前后阶段组合”为新颖性，仅回答本模型、固定 mask 下的可证伪问题。
