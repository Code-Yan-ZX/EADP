# Evaluation image grouping and split preparation

This CPU-only preparation reads image bytes, image identifiers and question IDs from the three local benchmark TSVs. It does not use questions, reference answers, model predictions, or scores. `build.py` records source SHA256, script SHA256, image byte and decoded RGB hashes, a specified 64-bit perceptual hash, all near-duplicate edges at Hamming distance at most four, and the resulting question and panel manifests. Original document/page IDs and AI2D variants sharing a figure name are joined; perceptual matches are conservatively joined with transitive closure. The group and question ordering follows the SHA256 rule in the experiment plan and the task priority DocVQA, TextVQA, AI2D. Split assignment applies to every question in a group, including overlapping tasks.

Run from the experiment directory under the bounded supervisor:

```bash
python monitor/supervise.py --run-dir NEW_SUPERVISION_DIRECTORY --timeout 2400 --snapshot-seconds 600 --poll-seconds 10 --disk /media/disk2 -- env OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -u data_manifest/build.py
```

Run `verify.py` after successful build completion; it independently reconstructs split selection and checks the source inventory and hashes, split isolation, pHash edges, and a 256-image brute-force neighbor sample. Review `manifest_summary.json` and `verification.json` before treating output as a frozen dataset. A successful file write alone is not proof of completed supervision; check `terminal.json`.

This is conservative, not a proof that all semantic duplicates were found. Similar-looking but different images can be grouped and reduce the available evaluation set. The evaluation datasets were previously exposed during the project, so FINAL is held out only within this study. TRAIN is not included; it must separately be deduplicated against all evaluation images before any training. The fingerprints are based on embedded TSV images. Cached image files may be re-encoded: the model input path and cached bytes/pixels require separate verification before generation. No model-inference, performance or accuracy conclusion follows from this preparation.
