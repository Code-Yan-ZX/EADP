时延从每次读取图片之前开始，到首个 token 选择并追加后同步记时；包含图片读取、预处理、视觉塔、选择及 decoder 首 token 路径。模型已加载并经过相应预热；未计入每次模型加载时间。四个预算采用已做三锚端点身份诊断的轻量 P3、DeepStack-on adapter，实际 adapter 调用本身的开销包含在时延内。K=1024 是保留全部视觉 token、绕过 greedy 的控制路径，仍经过其余 adapter，不能视为未包装原生实现或将 K 直接解释为计算量。

本 pilot 的生成完成时间在原始输出 fsync 后记录，包含该落盘开销；此处只报告首 token 边界，不将完成时间解释为纯模型端到端时延。三锚均为已观察的 DEV 样本，且三次重复并不能消除图像差异和主机负载漂移，也不构成总体置信区间或显存测量。

监督健康调用窗口以及约每 60 秒的 ps 查询和首个日志 fsync 窗口与 48 项的首 token 区间无直接重叠。第二次日志写入/fsync 及其残余影响未精确计时；主机还存在外部 Java 进程等背景负载，不能断言机器完全隔离或没有其他干扰。进程清单中的 CPU 百分比是进程生命周期口径，不能当瞬时 CPU 利用率。所有测次均保留，未按背景状态筛选。
