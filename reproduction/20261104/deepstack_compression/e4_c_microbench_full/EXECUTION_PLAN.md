# 32-image component diagnostic

This extension was decided after seeing the accepted single-image result. It uses the original `e4_c_microbench/schedule001.json` 32 DEV images, exact question identities and all 1,920 jobs in their originally frozen global order. The order values are additionally represented as 0–59 within each image solely to reuse the reviewed one-image checking contract; `global_order` preserves and is checked against the original schedule.

Each image gets a separate one-token diagnostic exposure, prefill and main/three-DS identity verification against the same E1 P3-D1 question, complete hook restoration, three warmups for each of three components, and 60 measured calls. The reference visual/input/prefill arrays are archived once per image, and every measured output is compared element by element to its reference at runtime and fingerprinted. Individual measured output tensors are not archived. A total of 32 exposures, 288 warmups and 1,920 measurements must be complete and independently reviewed before results are interpreted.

The prior pilot took 50.25 s including model setup, and its diagnostic archive occupied about 84.3 MiB. These numbers do not estimate the whole run. The frozen bound is 7,200 s within the retained container, 7,320 s for its supervisor, 1,200 s without journal progress, 90 s cleanup grace, and one health snapshot each hour, plus a minimum 15 GiB free disk. A launch must also fit within the user's original absolute three-day deadline and use an otherwise idle GPU. The test deliberately stops on unknown container state, source/identity mismatch, timeout, or missing/incomplete records. CPU and real no-GPU container preflights precede independent approval; GPU scheduling belongs to the parent.

Component timings are CUDA event intervals under warm-cache operation, not end-to-end TTFT. The `ds_injection` component covers the three selected streams and mask preparation, and excludes decoder DS additions. Hashes and output equality checks are outside the measured interval but can affect subsequent cache/thermal state. The E1 accepted DEV mixed journal is parsed for identity fields, not answers or scores; no new ground truth is read. No measurement should be presented as an unbiased experiment selected without the pilot.
