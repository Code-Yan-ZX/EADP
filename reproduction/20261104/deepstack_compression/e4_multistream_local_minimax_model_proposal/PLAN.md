# 32-image model-level falsification proposal — not an execution authorization

## Scope and fixed comparisons

This is a **posthoc DEV pilot**, proposed only after the four-stream feature-radius experiment and previous DEV results were seen. It tests whether its observed proxy difference survives actual model generation; it does not assert novelty, accuracy benefit, deployability, equal compute, or a confirmed result. The feature-space non-improvement stopping gate was not triggered, but that gate does not constitute evidence of model benefit. No model, GPU, new GT or prediction is accessed to write this proposal.

The full, non-replaceable denominator is the exact 32 previously accepted image/question identities in `e4_c_microbench/schedule001.json`: DocVQA 11, TextVQA 11, AI2D 10. Each must match `e4_multistream_local_minimax_v2/rows001.jsonl` by index, task, qid, group and archive SHA, and the previously accepted E1 input/processor and E4 K256 identity. Freeze hashes and completed formal/independent supervision for schedule, each 32-image archive inventory, minimax plan/results/independent proof, E1 input and relevant E4 K256 score provenance before any model launch; inspect full actual identity rather than infer from counts. Never change membership or drop a question because of feature values, outputs or quality.

Two new natural-generation arms on every question, for exactly **64 intended generations**:

1. Four-stream minimax, using the exact 256 spatially sorted IDs in each frozen `rows001.jsonl` row's `arms.minimax.ids`.
2. Main-stream-only minimax, using that same row's `arms.main_minimax.ids`, with the identical 2×2 one-per-block rule and spatial ordering.

For contextual comparison only, reuse the already independently accepted E4 K256 P3/DS-on result for the same question and input if its identity and generation recipe are supported by actual evidence. Its unrestricted EADP greedy selection does not obey one token per block. Never present it as a controlled local-allocation ablation, newly executed control, or equivalently costed measurement. If source identities or runtime controls cannot be verified, mark that comparison unavailable rather than assume equivalence. Top-left and fixed-random choices remain feature-space controls; this minimal 64-generation proposal does not add model arms based on observed outcomes.

## Model contract and identity

Use the same accepted Qwen3 model, checkpoint, processor, image bytes, task, question/prompt, tokenizer, input image grid, generation recipe, actual EOS and maximum output tokens across the two new arms. Bind the existing E1/E4 and 32-image formal/independent evidence and model/container sources by hash and their real supervisor exits. Each image must have the same 32×32/1024 pre-selection ordering verified against its accepted capture. At actual model execution independently check processor and all four actual full-stream tensor fingerprints against that image's accepted capture **before** relying on its frozen indices. Each selected set must contain exactly 256 distinct IDs, one per original 2×2 block, strictly spatially sorted, exactly equal to the relevant independently reviewed selection, and be applied to the main visual embedding and all three DeepStack streams with the same gather order. No claiming equality of embeddings between arms: their selected positions intentionally differ.

P3/DS-on must be the same adapter mode and decode procedure in both arms. Record and validate selected full-grid positions, actual 3-axis position IDs, attention/visual masks, RoPE delta, physical prefill/cache lengths, actual three injected DS fingerprints and resulting generation trace. P3 positions must be derived from each arm's own selected spatial indices using the same accepted mapping; they need not have identical numeric values across arms. Ensure the decode cache and positions evolve consistently and hooks/adapter state are removed after each case, including failure. For cases with identical arm IDs, require equal recorded gathered tensors/masks/position metadata; separately report output agreement without assuming bitwise determinism in advance. Synthetic tests should include wrong image/ID ordering, missing or misaligned DS, incorrect P3, decode-cache jumps, stale hooks and deliberately different IDs.

An existing selected-ID adapter may be used only after its real call chain, frozen-source identity and P3/three-DS tests are established. Some existing adapters compute and discard EADP greedy before overriding IDs; if retained, disclose and separately account for this extra work. Feeding precomputed IDs from archived features is a **controlled offline intervention**, not a demonstrated online selector: it presupposes all four full vision streams and does not measure selection, CPU/GPU transfer, synchronization or a deployable end-to-end path. A future live selector would need its own identity, total cost and numerical reproducibility validation.

## Unlabelled outputs, costs and stopping

Before running, independently review an executable plan, actual cwd/entrypoint, input and source pinning, complete CPU synthetic positive/failure tests, actual same-image no-GPU container preflight, GPU resource/timeout/cleanup and final verification/review chain. Parent alone schedules GPU; wait until competing strict timing and weight-I/O windows have ended. This is an instrumented quality/identity pilot, not a latency benchmark. Respect the project's `initial_plan.json` deadline and sufficient time for bounded cleanup, snapshot and independent review; otherwise do not start. Predict 64 generations plus a separately measured/reported one-time model load and any required warmup; no runtime estimate should be asserted without evidence.

For each intended case preserve immediately after generation returns the full raw token sequence and input length before decode/other processing, then generated IDs, decoded text, EOS IDs and whether EOS was reached, output token count, truncation/terminal status, errors and actual generate kwargs checked online. Keep per-case selected IDs, input and feature fingerprints, prefill/DS/position/cache checks, start/end and phase timings, selector/preparation scope, allocated/reserved peaks where available, device/container/source identities, and per-case hook cleanup. Clearly separate model-load, visual forward, gathering/injection, prefill/decode, any instrumented overhead and selection/transfer; unavailable components remain unknown. Do not infer TTFT, speedup or equal compute from these exploratory timings. Actual full high-dimensional tensors and full KV tensors need not be stored; identify what is online-only versus independently reconstructible from saved fingerprints.

All 64 cases count. An exception, OOM, missing identity, different underlying input or processor, mapping/position/DS/cache violation, incomplete output, bad cleanup, unexpected process/container exit or budget/deadline exhaustion stops execution, leaves partial artifacts and failure status, and blocks complete-panel or quality claims. No automatic retry, fallback, replacement or removal of hard examples. Publish completed/attempted/intended counts and only unlabelled identity diagnostics for an incomplete panel; a failed run cannot be silently joined to a later run. Infrastructure may be corrected and separately reviewed only under a new version with all prior output preserved.

## When and how scoring could follow

Generation and formal verification plus an independent full-result review must all really complete and exit successfully before opening or interpreting the new outputs for quality scoring. The user has authorized the attached DEV experiments and scoring: after complete generation, formal acceptance and independent review, a separately frozen and independently pre-reviewed scoring chain may open the existing DEV ground truth without asking the user again. A new answer's score **cannot** be obtained from E4's existing score alone; use only the existing authorized DEV labels and never read evaluation answers for training or rule selection. This proposal and CPU preparation do not open GT. No new labels, no training, rule/threshold/arm changes, or question selection based on DEV answers.

If scoring is later authorized, use the already independently validated task-specific metrics and preserve all 32 questions. Predefine the main paired per-question difference four-stream minus main-only, per-task means and counts, score ties/improvements/declines, output/EOS and ordered-ID agreement, and image-group paired bootstrap with fixed seed and iterations; report all three tasks separately (11/11/10), no pooled mixed-metric headline, unadjusted intervals and multiple-comparison/posthoc limitations. EADP existing scores are contextual, subject to its generation identity qualification. The small sample and reuse of observed DEV cannot establish superiority or non-inferiority; absence of observed gain and confidence intervals both constrain interpretation. No candidate is promoted, no downstream search is initiated, and the research line stops after this pilot if either independent panel acceptance fails or the four-stream arm has no observed benefit versus main-only across all predeclared task outcomes; if any observed benefit exists, it remains exploratory and does not automatically authorize follow-up.

Full-stream local coverage and multi-stream pruning have close prior work, including SPLIT-VLM, CoverPruner and METEOR cited in the existing feature RESULT. Objective improvement is built into the construction and may not preserve useful text or answer evidence; the one-per-block restriction can discard several critical tokens. PixelPrune is an existing pre-vision method and this full-vision intervention cannot be represented as its equivalent or as an original method contribution.
