# Post-DEV multistream diagnostic expansion and resource pilot

This proposal was developed after seeing prior DEV performance and the independent 32-anchor feature/correlation findings. Both the existing 32 anchors and the additional cohort belong to the same already-observed DEV set. The extension is post hoc, not a held-out validation, a deployable router, a training procedure, a threshold search, or an efficacy/significance claim. No new reference answers, model scoring, or predictions may be generated to choose samples or features. No GPU is authorized by this document.

## Cohort and precommitted pilot

Use all 384 question identities in the accepted E1 input manifest, grouped as 128 per DocVQA, TextVQA and AI2D. Require unique (task,qid), exactly 128 unique image groups per task, and identity agreement with all 32 originally accepted selector anchors on task, qid, group, image SHA and message SHA. Remove exactly those 32 *questions*, leaving 117 DocVQA, 117 TextVQA and 118 AI2D. Do not exclude remaining images based on other-task group membership; record cross-task group overlaps and pilot overlap honestly. Use a frozen task-local hash order SHA256 of `multistream-expansion352-pilot-v1|task|group_id|qid` with qid as deterministic tiebreak, and preselect the first three residual identities in each task as the sole nine-image resource/identity pilot. Include these nine as part of the full 352 if later authorized. No replacement, padding or filtering on failure, feature, score, length or timing is permitted. If source identity, quota, uniqueness or per-task group assumptions fail, stop and record failure; do not revise the selection retrospectively.

Plan/source and CPU-only tests, including actual accepted E1 input and 32-anchor manifest hashes and accepted formal/independent provenance, must be independently reviewed before actual sample extraction. Selection uses only previously verified input metadata (the input message exists in that metadata but is neither used nor saved). It opens no score files, feature values, prediction journals or reference answers. All sample identities and both the full eligible order and nine pilot identities are frozen before any new feature values or costs are inspected.

## Unchanged feature and analysis contract

Use the exact eight formulae and average-tie rules frozen in `e4_multistream_budget_diagnostic_v2/PLAN.md` and the accepted feature implementation: four per-stream norm coefficients of variation, three main-vs-DeepStack norm-rank correlations, and mean four-stream percentile-rank variance. Each of four streams must contain exactly 1024 position-aligned tokens; accept the same batch convention; finite values required. Undefined means remain explicit. Never tune features, task subgroups or routing thresholds from DEV values. K512-minus-K128 is the only score outcome; K256 is documented but not used to choose a feature. The planned descriptive report retains all eight features by all three tasks, all 384 identities and per-task denominators; undefined values and all errors remain explicit. No combined-task significance, feature selection, adjusted-threshold fitting, causal or deployability claim. This is an expanded same-DEV exploratory analysis; the first 32 were already inspected and the 352 are additional, not independently sampled confirmatory data. Track repeated groups and any cross-task overlap; do not treat observations as independent experiments.

## Future real-model pilot and full extraction requirements

The nine-image pilot must use the real accepted Qwen3 model and processor in the same backend, image size, prompts, generation controls and EADP configuration as the accepted E4 D1 reference, with a controlled diagnostic capture of main visual features and all three DS streams. Reuse the accepted selector capture mechanism only after verifying its complete real wrapper/hook call chain; removing needless selector or language generation is allowed solely after a separate keep-all/reference identity proof, and must not be assumed equivalent. The E4 panel has only hash/metadata for high dimensional outputs; independently check actual image/message, processor, main/3DS output metadata and fingerprints against the matching accepted E4 records and accepted E1 inputs; do not claim offline reconstruction of original full E4 arrays. All hooks must be removed on success, exception and partial registration. Per-image success, error, cleanup, source identity and model version are recorded with fsync; fail closed on mismatch, no automatic rerun.

Save the eight features, four 1024-element token norm vectors (or losslessly equivalent sufficient statistics for recomputing those features), input/output identity hashes, and cleanup/status only; do not retain full hidden-state tensors, answer strings or new labels. In a separate CPU independent review recompute all eight features from retained norms and compare. These norm statistics do not independently prove the original full tensors or their association with live model outputs: association is an online capture/hash identity claim and must be reported as such. Persist any pilot failure rather than treating its values as missing-at-random or selecting another case.

Record separate wall-clock durations for model loading, processor/visual computation, any unavoidable selector/language work, feature extraction, serialization and cleanup, plus peak GPU memory when available and explicit missing/unknown observations. The pilot is a cost/identity diagnostic, not a TTFT benchmark; no claim of GPU speedup, zero-cost features, or token-compute parity follows. Extrapolate full work only as a rough range from all nine cases including setup and variability, without silently excluding failure or treating repeat measurements as independent images. A valid executable runner, no-GPU same-image preflight, bounded supervisor/container termination, source/weight/input hashes and independent GPU prelaunch review are required before any pilot GPU. Main task GPU scheduling belongs to root. Full 352 extraction and subsequent score linkage require separate frozen execution/analysis gates and double acceptance; no partial predictions or results are scored/interpreted.
