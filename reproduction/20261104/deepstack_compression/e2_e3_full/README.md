# E2/E3 全 DEV 设计草稿

这是 CPU 合同准备，尚无 GPU 执行批准。沿用冻结 DEV 384 题的输入与作者生成配方，每题生成 E2 全部 8 个固定槽臂，以及 E3 的 PERM、MEAN 两臂，共 3840 个真实自然生成。E3 的 OFF/MATCH 直接引用**同一次全面板**中同题 E2 的 000/111 条目及其记录哈希；不把 E1 预测伪装成本轮生成。E1 的相同题两端点仍用于记录输出、选点、位置和首端点是否一致；一旦有差异须调查并另行审查，不自动宣称身份。

固定 3 个诊断锚点（每任务沿用已验收 smoke 预选题）保存完整原视觉/三路 DS、选取前及实际注入三槽数组，使 CPU 可独立重建。其他题仅保存每槽/干预摘要、原位选择、完整位置、输出和运行时选择及注入核验；这些非锚点的高维数组无法离线重建。各臂记录每步每层 KV 长度，但不保存完整 KV 数组。即刻 fsync 独立生成日志，后续观察与验证失败不得丢失预测。预计数组量须以 smoke 实测，预先检查空闲空间并设硬超时、停滞门、每小时健康快照；不把带观测的运行用于性能结论。

执行门必须绑定实际 E2/E3 48 臂 smoke、正式和独立验收以及监督器退出，特别是 6 对 33 token/36层真实 KV 内容指纹；E4-B 身份门也必须完整通过。冻结所有传递依赖及源哈希，经独立源码/CPU 反例审查、真实同镜像模型前完整 preflight 后才可考虑 GPU。中断不自动续跑或覆盖先前工件。

E2 的 384×8 和 E3 的 384×4（后者包含同次 E2 端点引用）分别核对完整题目、逐臂输出、注入证据、端点引用及实际进程退出。各自的正式验收和独立复核都通过前，相应评分入口不得解析预测或 GT；只解析 DEV 真值，bootstrap 和解释遵循事先冻结的统计计划。该设计不保证科学效果或解释为最终方法。
