This is preparation only. Neither these files nor the already completed 32-image pilot authorize the proposed 192-image GPU experiment or reading any future partial result. The pre-run analysis plan is `e4_c_multibudget_expansion192/ANALYSIS_PLAN.md`; its protocol was set after earlier DEV and pilot observations. The independently approved sample proposal `proposal002.json` supplies exactly 192 new measured images (64 per task), 30 old warmup images, 7,680 measurement and 240 warmup jobs. Preserve every job.

Before any target timing journal, generated-output file or label is opened, a future executable admission must fail closed on all of: (1) selection-plan/source freeze, completed CPU tests and independent proposal review with their exact source hashes and real supervisor exits; (2) the complete 888 freshly generated fixed32 references, their no-GT formal and independent review, source/snapshot/actual Docker exit and every same-identity/same-K reference hash; (3) future worker plan, every executable and transitive source, processor and input hashes, natural E4 same-input references, same-K generation configuration, frozen schedule and full dataset, plus unchanged code/weight observations; (4) actual full generation supervisor and container stopped/exit0/no OOM, complete 7,920/240/7,680 formal and independent no-GT result proofs with reviewer sources, started/terminal PID and command/output, source snapshots, and hashes of the complete journal and every required file; (5) independently reviewed environment-watch plan and actual observer started before model and stopped after model, clean supervisor/worker exit and same monotonic time namespace; retain raw ps output, watcher health, model health, explicit manual-check windows and exact file hashes. Any missing proof/termination/snapshot, changed source/record, partial journal, malformed source or absent observer data refuses analysis, preserving all artifacts.

Only after all those gates, parse the completed mixed journal for timings and output terminal counts. No GT is needed. Verify every started/raw/completed triplet binds to the exact proposal job/order and accepted same-identity natural or 32-token reference, time namespace, processor and endpoints. Keep per-job task/qid/group/K/protocol/phase/replicate and all three raw monotonic timestamps, output count/EOS/truncation, plus separately indexed TTFT and generation intersections for model health, observer ps query, query-to-first-fsync, observer health, and manual checks. Independently bind and report all raw observer and manual file hashes. Save every job including overlaps and warmups; obtain per-task/protocol/K counts without deleting samples.

Use hourly monitoring windows and manual windows as two separate statuses; an absent manual record or uncovered checkpoint is `unknown`, never zero or a passed check. Validate sequence and bounded timestamps in the same monotonic namespace. Absolute UTC comparison of observer/model start and end can detect missing coverage but cannot rule out host clock changes. Watcher's second fsync, manual log's own fsync, stop-marker write, light polling and residual host interference are unknown even when no recorded window intersects. State ps CPU percentages are process-lifetime averages.

The pure `window_detail.py` contract in this directory validates and annotates synthetic jobs but does not implement source authorization, dataset access, model work, file output or a CLI; it cannot itself unlock or run a model. Real executable gates, source bundle and CPU/actual-container tests, future reference and model runs, and an independent prelaunch review must be completed and frozen before any future GPU scheduling. Wall-time estimates and trial-size results do not replace that authority. The 192 expansion remains exploratory after seeing the 32-image pilot; no confirmatory or population guarantee is supported.
