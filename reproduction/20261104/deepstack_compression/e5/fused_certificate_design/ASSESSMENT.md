# Per-round certified fused greedy with whole-input fallback: design assessment

Status: read-only source analysis and proposed experiment, not an implemented certificate, mathematical proof for the actual compiled kernels, or GPU result. Do not modify the current candidate or its preregistered complete-ordered-output identity gate. Existing numerical samples cannot prove universal correctness. Current recommendation: investigate a conservative bound before investing in a GPU implementation; no fallback rate or performance is presently known.

## What must be proved

The author `pruner.py:_greed_select_impl` computes elementwise max, subtract, multiply, PyTorch `sum(dim=2)`, assigns selected candidates `-1e9`, and uses `torch.argmax`; initial coverage is zero and each winner updates it via maximum with the corresponding similarity row. `e5/fused_selector/kernel.py` evaluates a Triton `tl.sum` with a padded block, followed by PyTorch argmax and scatter. The source does not establish that PyTorch CUDA and the generated Triton code have the same reduction order, precision, rounding, exceptional-value behavior, or compiler fusion. Inspect the actually installed PyTorch/CUDA reduction implementation and the compiled Triton/PTX/SASS for the fixed N, hardware, dtype and compiler settings before claiming any bound. Re-prove or invalidate on any relevant environment change. Same input `sim_matrix` and `importance` tensors must be passed to both branches; upstream recomputation introduces additional errors and requires its own bound.

Assuming identical coverage at the beginning of a round, construct conservative, computable per-candidate intervals `[L_i,U_i]` containing the **author's actual floating-point** score, including intermediate max/subtract/multiply and author versus fused reductions. A fused winner w is certified only if `L_w > max(U_i for i != w)`. A raw top-1/top-2 gap suffices only with a valid single uniform bound epsilon on the absolute fused-to-author score error for every candidate: strict gap > 2 epsilon. When per-row bounds differ, compare against every competitor's bound; the raw runner-up may not have the largest upper bound. Intervals themselves need outward rounding or a proved enclosure; ordinary rounded FP32 bound arithmetic can understate error.

Under a separately proved finite, normal, round-to-nearest FP32 operation model, `gamma_m = m*u/(1-m*u)` with `u=2^-24` is a possible component of a sum error enclosure, with m chosen as a valid bound on actual rounded operations/depth, applied to the sum of absolute term magnitudes. It is **not** a complete certificate: bound subtraction and multiplication, both implementations' reduction trees and their difference, possible intermediate overflow, subnormal/flush-to-zero absolute errors, compiler FMA/reassociation, padded lanes, and max semantics. Either independently bound each result around a common mathematical sum or bound their exact operational difference. No proof here that the installed kernels satisfy those premises or that a useful bound can be computed efficiently.

If every previous round is certified and both branches use identical finite input rows and exact same max semantics, induction gives the same prior indices and coverage, so certifying the next round preserves the full ordered sequence and quota. If any round cannot be proved, mark the **entire image** uncertified and rerun the unmodified author selector from its original inputs; never resume from possibly different state. Prove eligibility and author argmax semantics, including first-index tie behavior for the actual version. Strict overlap/equality is uncertified unless a separate exact tie proof incorporates that rule. Multiple-image/batch semantics must be established independently.

## Adversarial and numerical cases

Author production similarity is computed by clamping cosine to [-1,1] then scaling to [0,1]; importance is shifted, normalized, smoothed, and exponentiated. Such source structure supports ordinary nonnegative finite inputs but does not itself prove all intermediates finite, all dtype behavior or nonnegative weights for every input/configuration. Negative importance or similarity need not make an interval bound impossible, but absolute-term bounds grow and the author sentinel `-1e9` can beat an unselected score; reproduce the actual mask and argmax semantics rather than silently excluding selected indices. Treat an actual NaN, infinity, invalid normalization, overflow, unsupported dtype/mode, or any unproved exceptional behavior as uncertified and run the original author path. Explicitly account for signed zero, subnormals, FTZ/DAZ, and exact ties; do not assume a mathematical order comparison reproduces either backend's `maximum` / argmax NaN semantics. Preserve author errors if fallback itself fails.

## Execution and cost

Each Graph replay can accumulate a device-side uncertain flag across all rounds and defer a single host read until before consuming the speculative selector result. If flagged, discard all speculative results and rerun the author selector from scratch. No pruning or generation side effects may commit before the flag is resolved. This design introduces at least a device-to-host decision/synchronization, certificate computation and memory, possible whole-input recomputation, and graph setup/capture/persistent allocator cost. Measure all of these in a separate controlled end-to-end experiment, including failure/timeout and the probability of fallback; selector-only speedup cannot establish TTFT benefit. A single final flag is sufficient only if all bound checks and state flags are correctly accumulated within the replay and accurately observed before downstream use.

## Preregistered experiment proposal, not yet run

1. First freeze a complete proof/specification for the actual operator, compiler/hardware and bound evaluator, and CPU unit tests. If a defensible enclosure cannot be established or only a bound too loose for useful certification is available, stop: empirical thresholds do not turn it into a proof.
2. In a separate diagnostic, freeze before inspection a representative accepted DEV image-group panel (for example the existing 128-image selector panel, K128/256/512) and all source/inputs/hashes. Include the previously observed K512 ordering mismatch as a named adversarial case, plus generated exact ties, near ties, negative weights, masked sentinels, signed zero, subnormals, NaN/infinity and overflow. Test all rounds, full ordered indices and quotas against actual author execution. Record count, round and cause of uncertified decisions; compare the whole final fallback output to author. Any *certified* discrepancy is a hard invalidation of this implementation and its claimed bound, not a successful fallback. Ensure each exceptional case follows its prescribed fail-closed path.
3. Report per K and input group the numerator/denominator of whole-input fallback, uncertainty reasons, margin distribution from diagnostics, and an interval for the observed fallback proportion. Repeated rounds on one image are not independent images. Do not fit or relax the bound on the test cases. Finite sample fallback rates neither bound future input risk nor prove correctness.
4. Only after source proof, independent review, genuine no-GPU preflight, real model endpoint identity and GPU scheduling, measure full-request overhead with the same preregistered data and include graph capture, memory, sync and fallback costs in appropriately separated setup/steady-state results. Retain failed attempts and do not infer real model accuracy or TTFT from this proposal.
