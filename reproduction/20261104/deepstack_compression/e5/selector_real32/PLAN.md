# EADP selector input validation and fused implementation pilot

## Objective and fixed scope

Use all 32 images and their exact question identities from `e4_c_microbench/schedule001.json` as a pilot; do not omit images because capture, numerical identity, latency, or candidate correctness is unfavorable. The eventual preregistered goal remains 128 DEV images × K={128,256,512}, or 384 real selection cases, plus duplicate-feature, exact-tie, near-tie, zero-weight and boundary-K synthetic cases. The 32-image pilot and any later choice to extend it are exploratory and occur after the initial 32-image selector timing was observed. Freeze the 128 identities and order before seeing this pilot's selector equivalence or speed. A possible deterministic extension is to retain all 32 pilot groups and choose the remaining groups by fixed task quotas and SHA256(`20261104|group_id`) among the existing accepted DEV panel, with one already frozen question per group; record exact quota and ordering in a new immutable manifest before running. Never select by accuracy, feature content, timings, or candidate agreement.

## Capture and data identity

The accepted 32 `e4_c_microbench_full/full_001/image_NNN/reference.pt` files contain processor input tensors, full main visual and three DeepStack tensors, actual compact prefill embeddings/positions/mask, and the K256 ordered IDs. They do **not** archive `VisualTokenPruner.forward`'s actual `text_embeds_llm` or `text_embeds_seq_llm`, so the text vector derived by mapping IDs into compact prefill is only a reconstruction. It must not be called measured selector input or assumed equal.

In a new isolated GPU diagnostic, execute the original accepted author wrapper on each of the 32 exact frozen DEV inputs, in the same model/backend and recipe, and register a pre-forward hook on the author pruner. Immediately clone and archive its four actual inputs: complete `image_features`, `text_embeds_llm`, `text_embeds_seq_llm`, and `grid_thw`; capture the full author outputs and the ordered greedy IDs separately. Save processor IDs/image grid, actual E1-comparable main/DS tensors and compact prefill, task/qid/group/message/image hashes, actual positional and injection metadata, generation exposure IDs, backend, parameter/source identities, and hook inventory before/after. Journal any diagnostic generation immediately and never score it. No CONFIRM/FINAL or GT is opened; accepted E1 DEV mixed records may be parsed solely for identity and this scope must be disclosed. A failed capture produces a per-image failure record; retain all 32 input denominators and stop/recover safely, never silently replace a case.

Independently reread all captured arrays, verify cleanup and clean Docker/supervisor exit, compare processor, main visual, selected IDs, actual prefill/position/mask and DS with the corresponding already accepted E1/E4 records, and compare K256 ordered picks against the completed 32-image capture. Separately reproduce instruction token IDs using the original author `_prepare_content` / `_tokenize_instruction` semantics, establish a unique original-ID-to-compact-prefill mapping, and compare the resulting sequence and mean **element by element, dtype and shape** against the pre-forward hook's real sequence/global selector inputs. Record a mismatch or ambiguous/nonunique tokenization as a failed reconstruction, not as success or an excuse to drop that image. The captured inputs remain the authoritative source, even if reconstruction fails.

## Numeric and candidate comparisons

For each image derive similarity and importance on GPU from its captured author inputs using the author's exact dtype, implementation, context, visual grid and reduction operations; archive both arrays and their metadata. Validate finite values, shape, device/layout and assumptions explicitly; unsupported cases remain failures in the denominator, not silently coerced. At K256, independently compare original full ordered picks and spatial output to the accepted per-image endpoint. For K128 and K512, compare the original selector and its spatial output to the same-question, same-budget P3/DS-on independently accepted E4 panel endpoint where available; verify tensor and input identity, never manufacture a pass when numerical or endpoint identity differs.

For all 32 × 3 cases compare author greedy to the one frozen Triton candidate on the same real importance/similarity, capturing every ordered ID, sorted spatial selection and any first differing step. Ties, zero weights and numerical edge cases must be tested explicitly. Record both identity and failed cases; preserve complete inventories for every planned image/budget even if an incompatibility makes later performance invalid. Any order difference is a different approximation, not a lossless speedup. The 96-case pilot is not the final 384-case claim. Do not generate quality predictions solely to compare selector implementations until the full input/selector identity chain is accepted.

For valid cases, benchmark author vs fused with identical inputs, warmup, fresh context and predeclared interleaved call order; retain every repeated output and event/wall time with hardware/software and monitor interference evidence. Avoid performance claims based only on successful cases when any planned identity fails. Report image as the unit when aggregating across repeated measurements. The M1 progression rule remains selector median at least 2× faster, true end-to-end TTFT at least 10% faster, and output identity; component timing alone cannot satisfy it. Full generation/output identity and independently supervised E4-style TTFT are separate later gates.
