# Fused selector: conditional round-by-round margin certificate

## Question and scope

This is a CPU-only research note, not a certified GPU implementation or an equivalence result. The candidate computes the complete ordered fused-graph selection; only if every round has a rigorously validated strict margin may that order be used. Otherwise discard the entire candidate and run the original author selector from the beginning on the same original inputs. The failure flag must be consulted before a selected order is used by the model. A CUDA error, invalid flag, abnormal exit, unsupported input, or incomplete check is a failure, not a pass. This policy does not change the already recorded K512 failure.

## Actual operations and evidence

The frozen author `_greed_select_impl` in `.../_reproduction/author_eadp/Qwen_vl/model/pruner.py` maintains float32 coverage, evaluates `maximum(sim,coverage) - coverage`, multiplies by importance, applies PyTorch sum on each 1024-element row, replaces already selected scores with -1e9, takes `torch.argmax`, and updates coverage from the selected row. `e5/fused_selector/kernel.py` instead executes the elementwise work and `tl.sum` in a Triton row kernel, then calls PyTorch argmax and updates coverage/selected mask. The graph version captures these same fused operations and copies actual inputs into static buffers before replay. The frozen prototype's outer validation requires finite 0≤sim≤1 and finite nonnegative importance; it does **not** prove importance≤1 or absence of subnormal intermediate values.

Cached `_gain_kernel.ptx` files under `e5/fused_selector/triton_cache` and `e5/graph_selector/triton_cache` contain `fma.rn.f32` in addition to subtraction/multiplication and shuffle reductions; cache metadata includes `enable_fp_fusion: true`. The existence of these files alone does not identify which exact cached kernel ran in every archived experiment, prove its final machine code, establish FTZ/subnormal behavior, or prove PyTorch's actual reduction tree. TF32 metadata for dot products should not be attributed to the gain kernel: this kernel has no dot product; upstream computation of sim/importance is outside the identical-input assumption. Freeze and audit compiler binary, exact specialization and deployed reduction code before assigning any rigorous error constant.

In the known TextVQA 35191 K512 example, first order divergence is zero-based round 332. Archived CPU reconstruction gave approximately 2.48e-9 difference between the two candidate gains in float64 and a float32 tie; the GPU's actual per-round gains were not archived. Both final K512 sets matched while order differed. None of these observations identifies the real GPU top-two gap or establishes the cause.

## Conditional mathematical argument

Assume identical finite float32 sim/importance bits and the same already-proved ordered prefix; non-NaN maxima then yield identical coverage, provided the two implementations update with the same PyTorch max/index semantics. Define exact real score for each unselected row `G_i = sum_j (max(s_ij,c_j)-c_j)*w_j`. Let `f_i` be the actual fused score and `a_i` the actual author score, with proven nonnegative error bounds `|f_i-G_i|≤Ef_i` and `|a_i-G_i|≤Ea_i`. If fused selects `b`, sufficient for the author to select the same unique `b` is

`f_b - (Ef_b+Ea_b) > max_{j != b, unselected} (f_j + Ef_j+Ea_j)`.

Equivalently with one uniform `E` bounding both implementations, the exact fused top-two gap must be **strictly greater than 4E**. Compare with directed bounds/exact binary rational arithmetic, not an unbounded FP32 subtraction. Equality, ties, zero gap, invalid/NaN/Inf, nonfinite/unknown bound, missing second candidate except the explicitly handled final-singleton case, or any unproven execution condition must fail closed. Original `torch.argmax` uses first-index tie semantics, so the strict criterion deliberately declines to certify ties. For T≤N and nonnegative finite scores, selected sentinel -1e9 cannot win while any eligible unselected candidate remains; otherwise use author fallback. Induction over all K rounds gives the same ordered greedy selection only if every preceding condition was truly satisfied. It does not prove downstream DS, logits or decoding identity.

One intentionally coarse **conditional** bound is `E = γ_(N+2) W`, `γ_m = m*u/(1-m*u)`, `u=2^-24`, `W` a rigorous upper bound on sum of nonnegative weights, assuming N=1024, 0≤s,w≤1, correct rounding, all nonzero relevant intermediate values normal, no overflow, and both compiled paths consist of the assumed bounded sequences of nonnegative products/additions (including separately justified FMA behavior). The actual GPU source/compiler/FTZ contracts have not been proven, so this is not a current GPU certificate. Under just those assumptions, `4γ_1026 ≈ 0.00024463242249879143`, hence strict gap >`0.00024463242249879143 W` is sufficient. Rounding of W and threshold must be outward and verified. A sharper per-row bound might help, but top-two alone is insufficient when per-row envelopes differ: compare the winner's lower bound to the maximum upper bound of **all** alternatives.

For illustration only, a read-only CPU check of the already archived K512 input found 1024 weights, exact-rational W≈373.7059420496 (min≈0.08357, max≈0.79559), producing the above conditional uniform threshold ≈0.0914205899. This illustrates likely conservatism; it is not a measured GPU top-two gap and cannot certify or reject that archived round retrospectively. No relevant FTZ/normal-intermediate assumption has been established for it. The `w≤1` restriction is a proposed conservative admission, not a property established by the general existing worker contract.

Even normal inputs can produce subnormal differences/products and partial sums. Checking all such intermediates at every round may require an O(K N²) scan and erode performance. One may instead develop and independently prove an outward-rounded absolute underflow/FTZ allowance; no such deployable bound is supplied here. Input range failure or unknown rounding/FTZ/FMA/reduction implementation means fallback. Near-overflow, Inf and NaN must also return to the author's unaltered path without silently sanitizing inputs or fabricating a result.

## CPU-only checks

`toy.py` uses Python `Fraction`, an explicit exact nearest-even binary32 normal/zero model, and an externally supplied `domain_proven` switch. It implements three toy summation sequences including an illustrative FMA, and a conditional exact-rational strict `>4γW` predicate. `test_toy.py` enumerates 1,458 pairs/trees for three-term dyadic examples and checks certified decisions against the toy author and reassociated/FMA variants, first-index ties, strict equality at the threshold, adjacent rational boundaries, invalid/negative/underflow rejection, and the N=1024 coefficient. `monitor_test001/terminal.json` completed/0. This finite toy is a counterexample finder for its model, not a formal proof, nor evidence of GPU rounding or performance. The switch is not a real proof that the domain holds.

## Proposed GPU evaluation, not authorized or run

1. Freeze exact model/selector input bits, compiler/toolkit/Triton/PyTorch/GPU specialization, PTX and machine code, reduction order and FP exception/subnormal behavior; compare recorded per-round author/fused score vectors and first-index ties on synthetic zeros/ties/nextafter/near-ties, low-magnitude/subnormal and overflow-risk inputs, changed-input replay and archived examples. Confirm every certified round against the actual unmodified author's prefix; an incorrect certification is a hard failure. Empirical agreement cannot replace the arithmetic proof.
2. Device-side record strict per-round bound failures and earliest failure. Complete captured K rounds before reading one final flag if using the present static graph, synchronize before any use, then recompute the entire selector with the original author on fallback. CUDA conditional graph nodes are a separate API/toolchain design and must not be assumed available through the current PyTorch path. Include top-two/upper-bound work, graph launch and copy, flag readback/synchronization, fallback full computation, peak memory and setup/capture in cost accounting.
3. Report full denominators, pass/fallback fraction by K/task and image, margin distributions, failure reasons, p50/P95 end-to-end request and TTFT including fallback, cold setup and warm reuse, memory and background uncertainty. Pre-specify success criterion and compare unmodified author, existing fused graph without claims, and certified fallback. Separate the already observed 32+96 development images from genuinely new validation images. No speed or exactness outcome is implied by this note.
