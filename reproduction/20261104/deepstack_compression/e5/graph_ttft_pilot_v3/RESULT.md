# 融合选择器 Graph：三锚首 token 试验

固定输入、Qwen3-VL-8B、P3 和三路 DeepStack、K256，三个 DEV 锚点；每锚每方法预热一次、测量五次，随机相邻配对，强制生成 32 个 token。计时从读取图像前到第一个 token 被选出，包含计时插桩，已预热的 Graph 首次捕获和常驻内存另记。

| 锚点 | 原作者中位 TTFT | fused Graph 中位 TTFT | 中位数变化 |
|---|---:|---:|---:|
| DocVQA | 399.451 ms | 362.977 ms | −9.13% |
| TextVQA | 353.626 ms | 324.965 ms | −8.10% |
| AI2D | 356.665 ms | 324.414 ms | −9.04% |

三锚各自中位数的中位数为 356.665→324.965 ms，下降 8.89%；这不是跨图的置信区间。18 对预热与测量的完整 256 个有序选点、32 个输出 token 均相同，正式监督退出且容器已停止，独立复核见 `../../e1_independent_review/graph_ttft_v3_result_review.json`。

首次 Graph 捕获 342.699 ms，PyTorch allocated 增加 4,201,472 字节，reserved 减少 16,777,216 字节；这些不是设备级峰值显存。输出在首 token 后持久化，因此生成全程耗时不用于性能结论。实验前其他用户的 Java 等进程有 CPU 活动，逐次重叠未知；仅三锚、warm-cache、固定 32 token，有插桩且未保存逐题清钩 inventory，不能推自然生成质量、普遍等价或完整 M1 成功。此前另一个 32 图试验中 K512 出现一例有序选点差异，虽然最终集合相同，已使预设的严格有序身份门失败，不能用本 K256 小样掩盖。
