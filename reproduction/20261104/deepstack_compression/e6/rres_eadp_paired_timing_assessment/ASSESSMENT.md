# R-res 512 与 EADP K256 同题性能对照：实现评估

这是在看到 DEV 质量结果之后提出的探索性方案，尚未冻结或运行。目标是在同一主机、同一题和一致的计时边界下，比较两个实际模型路径的自然首 token 与完成时间；不把同样保留 256 个视觉 token 当作等算力，也不以既有质量诊断中的运行时间代替性能测量。

## 可直接复用的依据

- `e4_c_multibudget_worker_v3/runner.py` 已验收的 `FirstToken` 和同步边界：原图读取之前同步并取 T0，首个 token 追加后同步取 TTFT，`generate` 返回后立刻同步取完成时间；后续再复制 token、落盘和校验。此 runner 的 EADP adapter、K 和输出约束是 EADP 专用，不能原样套在 R-res 上。
- `e6/pixel_natural_timing_pilot_v4/` 是独立进程运行不同模型路径、同题自然输出绑定和 CPU 合成验证的先例。其旧实现将 raw fsync 放在 generate 包装内，故**其生成完成时间包含 fsync，不能与上段的完成时间混用**；只借鉴控制/验收结构，重新固定共同端点。
- `e4_c_multibudget_expansion/pilot_plan001.json` 的 32 图为 DocVQA 11、TextVQA 11、AI2D 10，另有30张不重叠预热图；其五次图内中位数和图组配对分析在 `ANALYSIS_PLAN.md` 中有既验口径。采样和本选择均是事后探索，并非新独立确认样本。
- R-res `e6/rres_k256_dev384/` 全384输入和完整输出已经双验收；EADP 使用既验 E1 的同题 P3-D1 自然输出。逐次输出必须与**各自同臂**参考逐 token 相同、同 EOS/截断，绝不要求两个方法互相输出相同；同图 image/message hash 与六项生成标量、EOS 单独对齐。可复用 R-res 的 384 processor 预检及 P3/DS/mRoPE 身份证据，但不能由此证明新测量路径本身已过门。
- `e6/rres_k256_pilot_v2/arm.py` 是身份诊断，它在请求中做全张量 CPU 指纹、KV 观察和 raw fsync，不适合直接拿来计时。模型实际仍须使用已验收的512 processor 和原生作者模型，另做不计时身份比较。

## 建议的有界试验

用既有32图，两臂各五次，共320个测量请求；另沿用30张独立预热图、两臂各一次共60次预热。每任务把测量图固定分两块，每块各开一个 EADP 进程和一个 R-res 进程，合计12个独立容器进程；每进程只加载一种模型，预注册交错次序、输入顺序和两个块的臂顺序，尽量平衡加载顺序及时间漂移。各进程将本任务10个预热输入分配到两个块，每块5个；预热不得充当测量。每次请求重置 rope 状态，图片按真实作者路径重新读取，记录模型加载、预热、输出和每次计时。若单个任务或臂失败，保留完整失败和未运行分母，整个预定面板不宣称完整。

TTFT 和 generate 返回同步时间均使用上面的共同边界。另设从同一 T0 到**作者消息函数返回文本后同步**的时间，包含实际文本解码，才可称本机请求路径的文本完成时间；明确不含模型冷加载、排队、网络和展示。capture 持有返回 tensor，不得在 generate 返回同步和作者解码完成前为落盘作 GPU→CPU 复制或 fsync；作者自己的必要解码与同步属于请求成本。两臂记录各自长度，因自然输出长度不同，文本完成时间是实际工作负载对照而非纯算子速度。完整序列及时保存但只能在所有计时端点之后；若模型 API 的返回或失败导致无法兼顾，需要按预冻规则失败并报告，不改写端点。

R-res `generate` 返回包含 prompt 的完整序列；EADP 路径使用 `inputs_embeds`，其结果为新生成 token。前者按经过 processor 身份验证的 prompt 长度切片，后者不能再切 prompt；分别验证原始前缀及续写，避免误把两种返回格式比较。保持各自已验作者生成上下文；若因共同计时实现改变 `inference_mode` / no-grad、输出或预处理，应先在独立诊断中复核，不可为了更快而悄然改变。计时中的 stopping criterion、adapter 和其他包装开销如实保留；不要加入 token 数检测、processor CPU hash 或逐层 KV hook 的隐性干扰。

只在正式完成和双验收后，分任务报告图数、每图5次中位数的 R-res/EADP 比、绝对差、各臂长度/EOS/截断和全部原始样本；采用固定 seed 的图像组配对 bootstrap，重复不是独立图像，不做跨任务总体胜负或多重校正外显著性声明。监控窗口用同一时间命名空间匹配并保留全部样本，外部 Java、低频 ps/写盘、监督 health 和未能定位开销保留 unknown；不能将未观测解释为没有干扰。

## 实现缺口与最小准入

1. 分别做同臂无计时诊断：相同样本核真实 processor、512 结果 256 / EADP 选择256、三路 DeepStack 和 mRoPE/KV、生成配方以及与接受的完整输出。对实际 `generate` 返回格式、首 token 及文本完成边界做真实调用链合成/反例（缺首 token、前缀错误、EOS 错、方法交换和异常恢复）。
2. 新建受控主机调度和每臂 worker，做真实同镜像无设备前检，核模块导入、4片权重 stat/既验哈希、32图+预热身份、健康/超时、容器权限及12块次完整调度；CPU 合成故障覆盖缺题/重复、错臂输出、记录不完整和外部占用。若从静态流程无法确认端点，先做隔离三题 GPU pilot 并按该结果另行冻结完整面板；不可先行读取部分大面板进行选择。
3. GPU前冻结运行/正式验收/统计源码、完整随机日程、复核证明、资源预算和项目截止；时延时暂停本项目重 I/O 与并发 GPU，只使用有界低频 host watcher，列出监控本身开销。NVML峰值与本试验 TTFT 解耦；若额外采集，单独报告进程/整卡/图形占用、未知样本与漏峰，不伪装成精确峰值。

成本下界是12次模型加载、60次自然预热、320次自然完整生成，需另加无GPU预检和双验收。既往 Pixel 三锚 EADP 单次模型准备约7–8秒只是当时观测，不能作为本试验可靠预算；自然输出上限2048、长输出和12次冷启动均可能增加时间。以既验384同臂输出长度和少量独立 pilot 实测保守估计后确定硬限及用户截止，不能以速度结论反推删题。
