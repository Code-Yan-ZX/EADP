# R-res / EADP 同题时延前审检查清单

本文只供独立审查，不作为已冻结的实验计划或 GPU 准入。任何检查失败均保留对应监督/日志/已生成原始工件，不用删测次或只报告成功子集修复。

1. **研究问题和分母。** 32个既验测量图及30个独立预热图来自固定 DEV 源，按 task/qid/group/image/message 完整绑定；任务数量、图组互异、预热与测量图组不重叠必须逐项重算。随机顺序的 seed、组块、预热、臂次和重复次数在新结果前冻结，理论分母320测量、60预热、12独立进程；明确这是选择方案而非先前真实性能结果，不能外推全DEV。实际计划若调整数量，须先冻结新版本，测试严格按最终计划核。
2. **真实调用范围。** 两臂在各自新进程加载同一经验证权重/backend；R-res 仅按512 processor和本地作者基线，EADP使用1024输入、K256、P3/DS-on且核真实selector调用。每个请求从原图读取与processor开始，排除加载与预热；测量不打开全张量摘要、逐层KV hook、真实NVML或未经计时核算的诊断。输出自各臂既验同题结果逐token/EOS/截断核，跨臂不要求一样。既有的R-res全量结果是诊断参考而非全量时延。
3. **三端点和附加操作。** 同一单调时钟与时间命名空间：同步后在读取图前记T0；停止判据在token追加后同步记首token；generate返回后立即同步记生成完成；作者文本函数返回后同步记文本完成，严格 `T0 < first <= generate_complete <= text_complete`。分别确认 R-res 返回包含提示前缀、EADP仅续写。结果 tensor 仅持有引用；任何新增复制、hash、fsync都应发生在全部端点后。模型原本解码/复制的成本须算入文本完成。不得在失败后填补伪时间，也不得宣称包括冷加载、排队/网络或展示。
4. **可重复、完整和不干扰。** 每次校验自然生成参数、EOS和本臂输出，与原调用及hook恢复一致；实际末token、长度及全部原始测次均保留。不得先使用真实输出大小筛选图片、样本或计时。测时结束后数据持久化顺序/错误留证；内存中暂存导致的崩溃窗口需披露（不能声称所有生成结果皆能抗进程崩溃）。对真实结果不一致给完整分母/失败，不将其硬标为速度结论。
5. **测试与前检。** CPU实际调用链至少覆盖同步/时钟事件顺序、重复首token、缺首token、输入prefix错、零TTFT、端点倒序、保存过早、独立score标记，以及错臂输出；调度应拒绝漏题、重复、预热交叉、重排篡改、错任务/组别、错误臂次及重复序号。对停止判据还需实际使用项目所固定 transformers 版本的CPU假模型验证首token、EOS和对应输入长度；纯mock不能替代真实HF行为。对无设备容器按实际入口检查镜像、环境、全部挂载、无设备、模型未加载/CUDA未初始化、输入processor和四片既验权重身份。对运行中模型/GPU实际控制需另做真实受限三题pilot和独立审核，不将 CPU 测试当 GPU 通过。
6. **资源、噪声及结果界限。** 每进程硬超时/外层监督和截止；GPU独占前后检查、异常时容器停杀，加载次数和准备时间单列。健康监控/ps和第一/第二fsync窗口与时钟域披露；未知重叠不等于无干扰，保留外部Java背景及全部样本。显存若追加采集，须分别辨明进程/设备/图形占用、缺值、采样漏峰，与时延比较分开。统计先逐图五次取中位，再同图配对；按任务及图组bootstrap，不把重复当独立图，也不由等K推等算力。

三锚无计时身份结果已独立通过六臂，不代表32图计时已验证；EADP既有参考不含可比较的首个prefill logits，高维张量未全部归档。正式运行入口与独立统计计划仍须另行冻结、预检和审查。

当前 v4 实现的请求主窗口从同步后开始，EADP 逐请求 adapter 注册在此之前、退出清理在 response_end 之后，因此文本完成指标不包含所有准备和清理成本。实际 HF 配置的 `to_dict`/递归描述和逐token停止回调在窗口内；processor fingerprint、原图重哈及原始序列落盘发生在响应端点后，但可能干扰下次请求。模型加载窗须另记，不能仅凭model_ready推算。

逐请求干扰仅能对已经记录的有限操作窗口判重：采样器、GPU容器worker、自动health日志应分别记录实际时间命名空间及单调时钟源；命名空间不一致、覆盖不足或缺时标时标为unknown。记录窗口未覆盖的日志写入/第二次fsync、未记录后台活动和宿主其他任务继续标unknown，不能把未检出窗口解释为整机无干扰。`observation_oracle.py` 和 `monitor_observation_cpu002` 仅提供请求闭区间和观察半开窗口/未知状态合成反例，不是运行期观测证明。
