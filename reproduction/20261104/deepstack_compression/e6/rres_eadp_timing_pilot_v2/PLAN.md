# R-res 512 与 EADP K256 同题自然生成计时：可行性前检

此方案在已观察 DEV 质量后提出，属于后验探索，不用于训练、阈值选择或确认性推断。两臂使用已验相同图片、问题、自然贪心六标量及 EOS，分别核查各自同臂的完整已验输出；R-res 是 512 resize 后恰256，EADP 是1024原图处理并保留256，两者信息和计算不同。无需打开新GT，也不改变任何既有来源。

选用此前冻结的32个 DEV 计时图（Doc/Text/AI 11/11/10）与每任务10个不重叠预热图。每任务测量图和预热图分成两块，每块各自运行两臂；六块臂序交替 AB/BA，12个隔离模型进程，每进程5个不同预热图，块内每张测量图5次，共60预热/320测量。该样本与既有研究重叠，重复为同图重复而非独立样本。源顺序和固定种子排序在读取新时延前冻结，不能事后根据答案、输出或干扰筛选。

统一计时点：GPU同步后在图像读取和processor之前记 T0；第一个token选定后同步记首token；原生 `generate` 返回立即同步记生成完成，且不进行诊断tensor复制或fsync；作者消息函数自然解码并返回后同步记文本完成；然后才复制、持久化完整token并验证参考。后两个点分别排除和包含作者文本解码；模型加载、排队、网络和显示均排除。异常时若生成已返回，立即在脱离正常计时路径后持久化原tensor，再保留失败，不声称该请求完成。EADP 输入为 `inputs_embeds`，返回仅续写；R-res 输入为 `input_ids`，返回包含完整prompt，须先核前缀再切续写；绝不能跨臂要求答案相同或对EADP切prompt。

计时之外先通过三锚各臂真实同题processor、输出、P3/DS/缓存独立诊断；测量路径不得插入逐层KV或全张量哈希。每题文本端点之后保存实际processor四张量的哈希并与同臂已验参考比较、核原图哈希、首token长度及criteria调用次数；写盘与这些核验会影响下一次请求的缓存和背景，必须披露，未验证文件在读取期间的瞬态替换。每次重置前一题的RoPE/KV状态；记录实际方法、参考身份、完整输出、EOS与截断。无GPU processor/权重身份和真实同镜像模块入口通过独审、GPU/验收/分析/监督方案冻结后，方由主控安排GPU。监控健康窗、外部低频查询、首次fsync及无法定位的干扰逐项标注，所有样本保留。若跨图任一请求失败，完整分母失败，不重写/剔除。

最终仅在正式与独立验收后，先每图每臂5次各自取中位数，再按图组配对计算R-res减EADP和比值，报告三个任务及未校正 bootstrap、原始样本和自然输出长度；这只是单机的后验实现对照，不能直接泛化或宣称相同算力。当前代码是CPU合同/预检准备，模型GPU worker与最终运行门未实现，未授权GPU。
