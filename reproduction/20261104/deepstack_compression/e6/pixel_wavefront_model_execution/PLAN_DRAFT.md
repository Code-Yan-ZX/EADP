# Three-anchor PixelPrune wavefront full-model execution draft

This separate directory continues the frozen `.45` preflight without changing its source inventory. The threshold is fixed at `0.45` in the upstream identity worker's selector guard, the selected method call, the accepted-reference contract, and the author runtime environment. Another threshold requires a separately frozen plan and its own model-identity acceptance.

The future identity run must execute each of the three accepted task anchors in two fresh model processes, author then wavefront or a frozen counterbalanced order. Each process needs its own retained container, PID/start/cgroup handshake, hard deadline and cleanup; it must persist the started event, actual selector indices and the complete generated sequence before subsequent validation. The actual same-arm original selector output and generation tokens must match the previously accepted `.45` reference. Full prefill and three DeepStack arrays are archived; per-step 36-layer cache hashes and shapes are runtime fingerprints, not archived full KV tensors. Independent validation must reconstruct actual position/mask mapping, archived tensor bytes and each cache trajectory and compare both arms. A missing case or differing output blocks later timing, but remains in the journal.

Only after all six complete and independent identity acceptance may a *different* source-bound plan and approval authorize one warmup plus one measured natural TTFT generation per arm and image. First-token and synchronization boundaries, preprocessing, all monitoring, exposed outputs, and cleanup must be identical and explicit. Three selected DEV examples are post-hoc engineering diagnostics; no held-out answer, accuracy, significance, throughput, or generalized equivalence follows. Existing 32-image standalone selector identity is useful prior evidence, not model-level proof.

No GPU entry exists in this draft. The preflight proof and actual no-GPU retained container must be independently reviewed before this directory is frozen. Six-arm GPU execution also requires a separately reviewed launcher, complete source/weight binding, absolute user deadline, exclusivity, and root scheduling. This note does not authorize GPU.
