# PixelPrune 0.2 isolated-process timing runtime — draft only

This is an implementation draft, not an admitted experiment. The GPU entry is locked. Six identity arms were independently accepted earlier; their proof does not automatically authorize timing. The existing 24-job design is `../pixel_wavefront_t020_model_timing_v2/design001.json`: three anchors × two arms, one preliminary job and three measured jobs each, fixed randomized order. Every job starts a fresh model process and retained container. The preliminary jobs do not warm the later worker's in-process model or kernels. Never describe the measured runs as in-process steady state.

The host must validate the frozen 24-job list, absolute project deadline including all inner timeouts and cleanup, actual parent supervisor PID/argv/process group, source/weight identity and independent no-GPU and GPU prelaunch proofs before querying GPU, making output or running Docker. For each job, the reviewed bounded lifecycle must retain exit/inspect, record its unique full container ID and host PID/start tick/boot ID, check its actual argv/cgroup, release with an atomic file, reject competing compute and retain failures. The initial implementation only supplies pieces of this chain; the real launcher, gate, timeout constants and frozen exact commands are not yet wired.

The worker must immediately fsync all returned IDs before post-generation validation. Input length in that first file is taken from accepted processor shape and is provisional until actual processor is verified against that identity. Subsequent success requires the actual processor, complete ordered selection, token IDs, EOS and recipe to match the same-arm independently accepted reference. On failure preserve the raw IDs, error, logs, container and all earlier jobs; never write `all_completed`. The original source after generation validates input-prefix identity. The observer clones selected indices on device within both timed arms; this is instrumentation overhead, so timings apply to the instrumented path.

Only synchronized time from immediately before normal image read to first selected token is the speed endpoint. Output transfer and fsync can affect completion. Record absolute monotonic and wall-clock values, source hashes, query windows, time namespace, GPU and host background. Exclude other project heavy CPU, disk, container and GPU activity throughout actual measurements; unknown external load and any unavailable window remain unknown. Retain all observations. Three anchors and repeats are exploratory, and t=.2 uses a dynamic budget.

Separate later NVML run: six isolated model processes, explicit pre-CUDA host-PID/cgroup barrier and host sampling; bind actual six-arm identity, frozen sampler/controller and source provenance. Retain every query window and target-process/device values separately, distinguish graphics background and reject concurrent compute, report missing as unknown and maximum *observed*, MiB granularity and possible missed transient peaks. Save load/request/teardown stages; do not treat allocator as device memory. `nvml_stages.py` is CPU validation only, not an actual sampler or GPU path. Any CPU capture/synchronization in memory runs is disclosed.

Before any GPU run: complete entry/launcher and independent admission/real no-device preflight, source snapshot, watchdog and cleanup tests, separately freeze formal verifier and exact commands, pass independent reviews and reserve an uninterrupted measurement window coordinated by root. The accepted no-GPU execution v2 proof covers its own 368 sources only, not this new runtime draft. The CPU proof here covers only the listed draft files; it is not the model runtime or container proof. No GT or GPU was used in these tests.
