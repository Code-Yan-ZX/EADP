# Image geometry and R-res versus EADP: descriptive DEV diagnostic

Frozen after observing full DEV results, before extracting any individual image dimensions or joining scores. Use all 384 independently accepted R-res and EADP K256/P3-D1 scored questions (128 per task) with no replacement. Do not read any additional ground truth, train a router, choose a threshold from results, or claim causality. Both methods use the same original image and prompt, but R-res has 512px input and 256 visual tokens while EADP starts from the 1024-token visual input then selects 256; this is not equal-compute. R-res six generate scalars and EOS were checked online, while the full effective runtime config was not archived.

Use the already accepted E1 input manifest and its formal/independent provenance to map task, qid, group, message hash, image hash and original path to the accepted R-res design. For each of the 384 rows, read the original image file bytes, require SHA-256 equal to its accepted image hash, then obtain encoded width and height from those same bytes with Pillow. Do not apply EXIF orientation. Missing or mismatched images, duplicate/missing questions, unaccepted scores, changed source or incomplete supervision fail the whole diagnostic; no output based on partial rows.

Two separately reported descriptive groupings, fixed now: aspect ratio portrait if 5*w<4*h, middle if 5*w>=4*h and 4*w<=5*h, landscape if 4*w>5*h; area small if w*h<1,000,000 pixels and large otherwise. Per task report each subgroup's questions/image groups and mean R-res, mean EADP and their difference in percentage points, alongside complete-task means. Report all five groups including empty groups with null means; no significance tests, no threshold search, no pooled cross-task metric. Counts and mean score differences are descriptive only; results are posthoc, subgroup sizes can be small, many groupings/comparisons are considered and task/data composition can confound them. Do not infer a mechanism, causal effect, or generalizable route.

Inputs.jsonl contains prompts, and the already accepted mixed score JSONL contains existing predictions; those files are parsed only for identity/scores. No new ground-truth source is opened. Every result is independently recomputed after the bounded supervised run.
