## Scheduling and isolation

Use a fresh process and model instance per arm/anchor, no other GPU workload; do not preload three patched models concurrently. For each of three task anchors, choose a reproducible seed-fixed random permutation of the three arms, with all three adjacent as a paired block. Each process performs one same-input warmup generation followed by one timed natural generation. The pilot thus contains 9 warmups and 9 timed calls, 9 separate GPU processes; a CPU-frozen schedule must be generated and checked before launch. Disclose that a single warmup may be inadequate and that three images provide no population speed conclusion. Process startup/model load, any graph or compilation, and warmup are excluded from per-request TTFT and reported separately. Document page/kernel/cache state, arm order and time; process isolation does not erase shared host filesystem/kernel caches. Record timeouts and missing/failed calls; never drop or substitute them.

TTFT begins immediately before actual image read and author message/processor construction, after one GPU synchronization to close preceding work. The terminal boundary is one synchronization and monotonic timestamp in the actual stopping criterion after the first selected token has been appended. Verify generation source/version and runtime criterion length against prompt length. The interval includes input processing, data movement, selector, the actual vision computation, DS and decoder prefill, and first-token selection. Generation to EOS proceeds afterward with identical control; write raw output only after the boundary, with no hash/FSYNC or per-layer probes inside the measured interval. Report host elapsed end-to-end separately only if output persistence is outside that endpoint and its inclusion rules are fixed; no per-component timings inferred from TTFT.

## Dynamic K and resources

Pixel's selected merged-token count and EADP's 256 must be attached to each actual measured call. The existing Pixel patch `_store_dedup_stats` returns without retaining those values when verbose/logging are disabled; enabling its profiling is intrusive. Therefore a minimal, exact live count observation must be designed and tested, with no added device-to-host synchronization during TTFT and no per-layer tracing. If the count is unavailable without such intrusion, mark that sample's K unknown and prevent claims that it is measured, and run a separate identical-input diagnostic that records the selector and three DS row counts. Independently compare observer-on versus observer-off endpoint outputs and explicitly disclose CPU wrapper overhead. Do not infer actual K from an old full-panel prediction when per-call K is unavailable.

Use a separate 9-job GPU-exclusive memory phase with the same schedule/recipe and separate fresh processes to avoid NVML polling in TTFT. Worker reports CUDA allocator baseline and `max_memory_allocated` / `max_memory_reserved`, including explicit reset/synchronization boundaries and model-loading/setup retained separately. A separately supervised host sampler binds actual container, GPU UUID, host process PID and process start identity, covers initial/terminal queries and all gaps, and saves raw timestamps. Report sampled per-process usage, device-wide used/total, other graphics/process occupancy, known and unknown sample counts separately. NVML is sampled and can miss peaks, device used is not process-exclusive, and allocator statistics omit non-PyTorch allocations. Real NVML/controller handshake and its full GPU permission remain unfinished; a prior fake-sampler proof is not a real memory measurement. No comparison until that gap closes.
