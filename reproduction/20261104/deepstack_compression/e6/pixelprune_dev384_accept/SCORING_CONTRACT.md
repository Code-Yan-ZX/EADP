# PixelPrune DEV384 scoring contract

Status: preparation only. This document does not authorize reading labels or executing scoring.

1. Generate all 384 frozen E1 DEV inputs exactly once with the source/weights/processor identity and E1 natural-generation scalar checks. The separate acceptance step must validate every output, tokenizer re-decode, EOS or the 2048-token cap, dynamic visual K, recorded model-position/KV lengths, actual runtime visual/DeepStack injection checks, complete identity inventory, and clean supervisor and Docker exits. Incomplete, duplicate, failed, or unauditable records block scoring; failed questions are not omitted or replaced.
2. Before any prediction or answer is opened by the scorer, require the complete formal no-GT acceptance proof, its actual started/terminal records, a separately supervised independent review of all 384 records and its actual exit, frozen run/acceptance/scorer source hashes, E1 DEV input and scoring-source identities, and an independent CPU prelaunch review with negative tests. Recheck all bound hashes. Score only selected DEV question IDs using the existing accepted E1 author plus independent scoring implementation and its exact XLSX/pandas normalization. Never decode CONFIRM/FINAL answer values.
3. Write every question's raw prediction, dynamic K, official score and independent score; require finite official/independent agreement within the existing 1e-12 tolerance. Preserve all 384 denominators and summarize EOS, cap truncation, empty answers and K distributions per task. Use image group as the unit of paired comparisons/bootstrap, with a fixed seed and replicate count frozen before score results are examined. Report task results separately; label all comparisons after observed DEV experiments exploratory and unadjusted unless an independently frozen plan states otherwise.
4. Any comparisons to E1/E4 or other selection methods must bind identical question/group/message/image/processor identity, natural-generation scalar/backend and accepted source/exit evidence. Report dynamic token budgets and their distribution alongside accuracy. Threshold-zero PixelPrune is not an equal-K256/equal-compute baseline; no speed, cost or held-out performance follows from this instrumented panel.
5. Preserve the single-image same-model after-load disabled identity diagnostic and the three-task patch-before-model natural pilot as different experiments. Their limited scopes do not prove all 384 examples are equivalent to either stock or author original. The full run's high-dimensional tensors are retained only through processor hashes and recorded runtime checks, so they cannot be reconstructed element by element after the run.
