# PixelPrune anchored selector: 32-image GPU expansion

On the 32 previously examined DEV images at threshold 0.45, the local antidiagonal implementation, pinned author GPU selector and CPU reference returned the same complete ordered selection for all 32 images. This expands the four-image GPU pilot after its results were seen, and includes those four images; it is not a fresh independent sample. The candidate changes how the author’s anchored recurrence is executed and is an engineering optimization, not a new pruning method.

Each image received one synchronized host-wall measurement per implementation, alternating order between images. The author’s selector had median 184.18 ms (range 177.60–220.73 ms); the antidiagonal implementation had median 28.81 ms (28.60–31.58 ms). The median of the 32 within-image author/candidate ratios was 6.38. Each implementation got a tiny 3×3 warmup before the measurement; the input normalization, data transfer and full model were outside the measured interval. One observation per implementation and image is not a repeatability study. The worker retained elapsed durations but not the raw clock endpoints; host process snapshots before and after cannot establish which background activity overlapped individual calls.

The source plan and actual inputs are frozen in `plan001.json`; all 64 timing records and complete ordered indices are in `run_smoke001/observations/`. Independent source, selection and terminal review is `../../e1_independent_review/pixel_wavefront_gpu32_v2_result_review.json`. The reviewer is independent of the candidate and this 32-image worker author but previously authored the four-image worker on which this worker was based. Full-model output, DeepStack/position/cache identity, end-to-end TTFT and generalization remain unverified by this component test.
