# 随机 K256 完整 DEV 面板：待批准的执行设计

本设计是在已有 DEV 结果观察后提出的探索性基线。固定 384 题、每任务 128 题及冻结的三个种子；每题对三个 seed 独立生成自然输出，共 1,152 臂。三任务小样的 9 条自然输出不能自动复用为全量结果：初版全量计划全部重新生成，避免把单题身份门当作逐题证明。所有预测生成、真实容器和监督进程完整退出、正式无 GT 验收与独立复核均通过后，才可依冻结评分计划读取 DEV 标签。保留 EOS、截断和空答及完整分母。

选择器以 image SHA 和固定种子经 SHA256 与拒绝采样 Fisher–Yates 生成 256 个不重复的空间升序索引；全部 1,152 个输出索引已冻结。每题比对正式验收 E1 的同题图像和消息、processor、视觉主流及三 DS、原始位置和原生 EADP greedy；原 greedy 在该适配器中实际运行并被弃用。以 K256 / P3 / DS111 使用同题同模型同实际 generation controls（包括 EOS 和停止条件），记录原始生成 token、确定性选择、所有 P3 位置、三路 DS 的运行时检查及摘要、实际逐步 KV 长度、终止状态和失败。不得把本 adapter 的运行时长当作随机算法成本或直接与 EADP 比速度。

全量输出生成后立即落完整 token 并 fsync；后续验证失败必须保留该暴露，不能跳过失败题或自动重跑。正式面板只保留高维摘要和哈希、真实完整索引/输出与逐步缓存长度；高维完整数组和强制 33 输出/32 decode 的 KV 指纹只存预定 3任务×3seed 小样，不能声称全量张量可离线逐值重建。所有完整小样先验收，再为完整面板固定独立源码、输入清单、实现、容器画像及预算，做同镜像无 GPU 模型前预检和独立审查。运行时单 GPU 独占、有界总时限与进度停滞、Docker stop→kill→inspect 和用户三天截止，按真实小样耗时和磁盘/显存预估后再决定能否启动；不随结果挑选 seed 或缩减样本。

评分计划应在完整面板结果读取之前冻结：逐题各 seed 与作者及独立指标核对，对 E1 P3/DS-on 同题比较，以图像组配对 bootstrap，分别报告每个 seed、三个 seed 的题内平均及每任务分母；三个固定 seed 的离散程度只描述 seed 敏感性，不能当作独立图片样本。该比较为后验 DEV 探索，不是确认性结论或等成本速度比较。现阶段仅设计，不构成全量准入、GPU 调度或结果。
