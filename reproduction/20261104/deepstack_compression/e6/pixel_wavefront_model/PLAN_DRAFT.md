# Pixel anchored wavefront: model identity and natural TTFT draft

This is an engineering modification of the existing PixelPrune anchored `pred_2d` `max` selector, not a new pruning algorithm. The three existing t=.45 DEV diagnostic images are DocVQA 16539, TextVQA 39421 and AI2D 368100. The selection and this expansion follow observed DEV and four-image component results. These three cases are not a representative or confirmatory sample; no labels or scoring are needed.

The diagnostic has two strictly separated stages. Neither is authorized by this draft; the actual runnable sources, plans, CPU tests, same-container no-GPU preflight, process isolation, supervisor and independent prelaunch reviews must first be frozen and checked.

1. **Identity, before timing.** For every image, invoke the actual author `pred_2d` anchored-max at t=.45 and the wavefront implementation from separate fresh model processes, both patched before model loading in the same Qwen3-VL backend and using the same frozen processor/greedy generation recipe and EOS. Preserve actual 1024-coordinate ordered selector output from the method actually called. Check each against the independently accepted t=.45 control and compare the two implementations on the same input. Immediately fsync raw full prompt and generation IDs on `generate` return. Save and independently reconstruct actual prefill main embeddings, three injected DeepStack tensors, masks and three-axis P3 positions using original/selected index mapping; check model rope delta. Collect per-step 36-layer KV length and byte fingerprints, distinguish fingerprints from archived full KV bytes, and compare same-input native/wavefront natural tokens, logits and cache fingerprints for every corresponding step. Retain any failed or interrupted case and stop admission to timing if any identity/control is missing, differs or cannot be audited. This binds the actual model path; CPU and standalone component equality do not substitute.
2. **Natural timing, only after all identity jobs and an independent identity review have completed successfully.** Use one fresh isolated container/process per image×implementation, fixed interleaved schedule, same image/processor/scalars/model and same verified method implementation. Each worker loads model and does one unmeasured warmup and one measured natural generation, preserving full raw tokens immediately after return and verifying against that arm's accepted identity. Instrument the first generated token with the same measured synchronization boundary and count/observer policy on both arms. Record setup/model load separately, the precise start/stop/end and wall-clock semantics, runtime actual K, complete output and any truncation/failure; do not silently exclude any planned job. Bind actual container PID/start ticks, GPU exclusivity, real timeout, cleanup and monitoring. All numbers are three-anchor pilot measurements; no population uncertainty or throughput claim follows.

The author selector's `.item()` synchronization is part of its actual method cost; include matching caller, normalization and selection on both methods in end-to-end timing. Processor and image loading belong in TTFT if they were inside the original frozen start boundary and must be disclosed. Identity tracing, hashing, forced archival, extra synchronization and recording costs are forbidden from the timed interval unless present symmetrically and explicitly disclosed. Whole-model timing may differ from standalone component gains. Memory allocator statistics are not device-wide NVML peaks. Preserve all background-process intervals available and do not infer interference from before/after snapshots.

No GT, held-out labels, quality decisions, GPU launch or overwrite of existing evidence is authorized by the preparation stage. Any failure in validation or identity is a recorded diagnostic result, never an excuse to claim equivalence.
