# Proposed warm-process PixelPrune author vs wavefront timing

Status: **proposal only, not frozen and not run**. The earlier 24-process, three-anchor isolated-load TTFT results were inspected before this proposal. The separate full-DEV 384-question wavefront equivalence run has not yet been performed. These conditions make this follow-up exploratory, not preregistered independent confirmation of the original finding.

## Question and design

Measure whether the original τ=0.2 selector and its wavefront implementation have different end-to-end first-token times under the same warm-process conditions and same questions. This is an implementation comparison, not comparison of equal FLOPs across different budgets, a model-quality claim, or a claim against EADP. Each matched question must have identical inputs, backend and generation settings; retain actual selected count and ordered positions. For measured records, collect the first generated token and EOS status and record mismatches; separately check any available full-DEV comparison before inferring broad equivalence. The warm study cannot prove equality of full generations or latent KV tensors.

Fix a 192-question cohort in advance: the existing independently accepted 64-per-task EADP timing cohort, independent of the four-stream association and without choosing on answers, score, speed, or wavefront similarity. Confirm group uniqueness, input hashes, full panel acceptance, and exact exclusion or overlap with any warmup question; disclose overlap. Keep every selected identity and no replacement, and preserve original order/selection evidence. This cohort overlaps prior timing studies and is not a held-out dataset.

Before looking at any new Pixel timing, deterministically partition each task's 64 identities into four blocks of 16 using a published hash seed and full task/qid/group/image identity. Each block has all three tasks (48 questions). Execute two fresh model processes per block, one per arm, with the same block question order. Alternate arm order over the four blocks as AB, BA, BA, AB (or a separately frozen balanced equivalent) to reduce monotone drift. For each process load the model, perform a separately recorded excluded warmup using a predetermined fixed valid question, then measure every one of the 48 questions once. Loading is outside the timing boundary. If the engine needs process-level patching, apply each arm before loading its own model. Use same dtype, backend, prompts, decoding and synchronization. Do not pool these samples with previous isolated-process measurements or call a warmup proof of universal steady state.

TTFT starts immediately before image read and ends after first token selection and CUDA synchronization, consistently for both arms. Explicitly specify which CPU copying, result serialization and file flushes are excluded. Record complete per-question first-token time, selected count, processing identity, first-token identity, real process/arm/block order and supervisor timing. Separate cold start/model load, if recorded, from TTFT. Both arms must carry the same instrumentation; capture overhead must be disclosed. Keep all samples; failures invalidate complete analysis rather than trigger replacement or selective deletion.

## Limits and planned analysis

Require all 384 measured records (192 questions × two arms) and eight real process exits, any declared warmups, formal and independent result reviews before reading or interpreting timing values. Compare paired wavefront minus author per-question first-token time by task: median paired difference and paired ratio, per-image paired bootstrap interval resampled by image group (e.g. 10,000 fixed-seed draws), without treating within-image runs as independent. Report marginal medians separately; median paired difference is not difference of marginal medians. Include all per-question data and distributions; no P-value, multiplicity-adjusted claim, or universal latency conclusion. This is a single GPU/back-end, one measured observation per image and arm and four time-separated blocks; GPU background and order effects remain possible. Do not infer memory or quality from TTFT.

Before GPU: implement and freeze execution and descriptive analysis, real input/preprocessor identity checks, complete denominator, deadline and timeout, actual no-device container preflight, source provenance, full GPU/formal analysis prelaunch and independent review. Record GPU and system-health observations with monotonic windows; avoid contaminating measured windows where feasible, and disclose observer/supervisor/fsync and unsampled background uncertainty. The user's hourly check takes precedence and its windows are recorded; no unlogged monitoring. This proposal alone does not authorize reading incomplete outcomes or launching a test.
