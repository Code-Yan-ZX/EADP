## 全量执行和评价

1. 保持原 384 题的任务与顺序、每任务 128 题及全部分母。相同输入、同一作者包装模型、Qwen3-VL-8B-Instruct 权重与 processor、bf16、flash_attention_2、同设备类型（原为 A40）、图像预处理、原 PixelPrune `pred_2d/max/anchored/τ=.2` 和逐题实际生成参数。原参考的 `max_new_tokens=2048`、greedy 设置、EOS 与配置需在执行入口和每条记录中逐项核验，不仅凭计划文字假设；固定镜像、依赖、权重与 recipe 身份。除 selector 实现外不有意改变算法。
2. 将波前 selector 接入作者真实分支；对每题保存真实顺序选点和数量、processor/输入身份、P3 位置、三路 DS 对齐与实际 KV 长度/位置摘要、清钩状态和输出终止条件。每次生成返回后先落盘并 fsync 完整返回 token 序列及输入长度，再进行前缀检查、比较和解码；保留异常及真实退出链。
3. 与同题已验原运行逐项比：完整有序选点、选点数、生成 token 序列、EOS/截断状态和解码字符串；逐项报告相等、不同、未完成以及异常。token 不同而字符串相同须单列；不把集合相等说成顺序相等。processor、位置、三路 DS 和 KV 仅在双方确有同口径记录时比较；其他用新运行在线检查并明确其边界。
4. 语义不一致不是成功：保留该题双方证据与失败类别，记录完整分母并继续处理其他安全、身份有效的题；系统/输入身份错误、资源故障或监督超时则安全停止，未执行项标记 `not_evaluated`。不覆盖、不自动重跑，也不按通过案例筛选。事先固定必要的失败诊断流程：可另行在同环境对不一致题跑作者控制，记录原有不一致，不把事后复测替换原结果。
5. 若全部题生成 token 和 recipe 均相同，可按题复用已独立验收的原分数，说明这只证明本 DEV 的等输出及等分数。若任一输出不同，不宣称质量相同；任何需要读取 DEV 标签的新评分均须在完整双重无 GT 验收后另设冻结方案并获调度，按全部题与任务报告配对结果、分母及图组 bootstrap。没有训练或调阈值，此比较仍为已观察 DEV 后的探索。

## 资源、监督和预检

原 384 题作者监督实测约 275.5 s；其 observations 目录约 32.7 MB。三锚六臂诊断监督约 145.4 s，包含多个模型/容器启动，不能直接换算全量耗时。波前 384 题尚无实测；模型加载、选择器、仪表、逐题 fsync 及环境差异都会改变成本，上述均不是加速/TTFT 结果。建议单次模型加载、保留每题独立产物；预留至少 10 GiB 空间并在准入前检查实际资源。候选外层 3 h、内层 2 h 55 min、停滞 20 min、终止宽限 90 s；这些是待审的上限，不是预期耗时。必须结合用户三天截止、实际空闲 GPU 和有界收尾判断是否有足够余量。还需约 20 GB 权重顺序哈希及身份核验 I/O，与其他任务错峰。

实现需采用 PID/容器状态真实监督、外部 SIGTERM/SIGINT 与超时 stop→kill→inspect、退出码和 GPU 进程清理；输出源快照、逐题事件和完整 supervisor started/terminal。先做实际 cwd 的 CLI/导入纯 CPU 回归，覆盖 384 完整分母、选点/输出不等、出错后 token 留存、hook 清理、终止与保留未执行项；再执行同镜像无 GPU 预检，验证输入/processor、四片权重、来源、命令和真实容器无设备退出。GPU 前需独立审查完整执行/验收计划和真实 preflight；运行结束后先正式无 GT 验收，再用独立实现逐题复算与复核真实容器/监督退出，双验收后方可汇总。当前仅为后续建议，尚无任何 GPU 启动授权。

历史参考与候选并非同一时刻交错测量：即使校验同镜像、版本、设备及输入，若输出不同，也不能仅凭差异断定由波前算法造成；需保留设备、软件和运行状态以便诊断。本实验不提供等算力或时延收益结论。
