# Pixel nine-process NVML host candidate — CPU only

This directory is a prototype. It does not query a GPU, invoke Docker, open model weights or answers, or contain a GPU launcher. It consumes only the frozen nine-job design and synthetic records in its test. It is neither an admission nor a frozen/independently reviewed execution plan. A standalone successful CPU result cannot establish that an actual run is clean.

## Interface

* `host_contract.validate_design(jobs)` checks the ordered three-anchor × three-arm grid, matching input identities across the arms, and 64-digit hashes. Bind the full bytes/hash of `e6/pixel_wavefront_t020_nvml_nine/design001.json` separately; structural validation cannot prove the canonical design.
* `run_nine(jobs, run_one, record)` injects a future reviewed single-job lifecycle, runs sequentially, durably records results through the supplied callback before advancing, rejects reused container ID, nonce and `(boot_id,host_pid,start_ticks)`, and aborts on failure. It does not itself implement persistence, bounded waits, interruption, container cleanup, or GPU access. `run_one` must always retain raw failure evidence and finish bounded cleanup before returning or raising; `record` must provide durable atomic/fsynced evidence. Booleans in the result are contract assertions, not proof; a separate verifier must inspect each raw lifecycle artifact. Callback errors can prevent even the failure entry from being persisted and must not be interpreted as a clean exit.
* `stages.summarize(samples, target_pid, uuid, bounds, max_gap_ns)` validates already sanitized metadata. The first query must finish before release; the last must bracket the teardown end. Each query is bounded and a conservative sample spacing is the following query end minus the previous query start. It reports that spacing, the query durations and inter-window gaps. Empty stages, absent target, and present target with unavailable memory are distinguishable from zero. Graphics PIDs are retained; any observed foreign compute or unknown process type fails. It separately reports overlapping and fully contained query indices. **Overlap maxima may include samples outside a stage**; exact within-query sampling time is unknown. Unknown values and empty stages produce `None`, never a zero peak. A summarized stage with no fully contained sample must not be treated as complete coverage without an explicitly reviewed rule.
* `validate_budget` requires an outer bound that accommodates all remaining per-job bounds and final cleanup, inside the absolute wall-clock deadline. Example only: if a per-job supervisor timeout is 1680 s and can consume a further 90 s grace, nine jobs need at least `9 × 1770 + 90 = 16020 s`; this is not a commitment to those bounds. Signal handlers, cleanup timeouts, sampler limits, disk and absolute remaining budget must all be reconciled with the actual executable.

## Existing lifecycle to integrate and review

`e4_c_memory_model_pilot_v2/controller.py` uses `e4_c_memory_real/controller.py` and the bounded `e4_c_memory_runtime` primitives to verify running Docker config and host PID/cgroup/argv, wait for pre-CUDA worker readiness and supervised sampler's first sample, atomically release the bound identity, observe worker exit, stop/kill on failure, verify stopped container/PID 0 and sampler terminal, and sample after exit. The candidate here is not that adapter. In particular, `construct` currently accepts only `C-ON` mode; do not assume it supports the Pixel modes without changing and testing the actual handshake. The sampler's XML source currently rejects an unavailable compute-memory field rather than recording a successful target-unknown sample; a future integrator must either preserve that fail-closed behavior or explicitly revise and test the full sampler/contract pair. A graphics observation, and even an otherwise clean set of samples, does not exclude interference between query windows.

## Before any GPU run

Complete a real worker for each arm with reference identity and ordered selections, gate source/proof/weight identity, actual supervised lifecycle adapter and nine distinct retained containers, raw outputs, and same-image no-GPU preflight. Freeze and independently review the complete executable source, bounds and sampler; have a separate formal post-run verifier independently check the actual container inspect, PID/start/cgroup/argv, release/UUID, samples and worker identity. Sampled process and whole-device memory, PyTorch allocator values, MiB resolution, absent/unknown fields and graphics background must remain separate. CPU copies and synchronization perturb memory; this is not a TTFT experiment. t0 historical records do not establish the full selection ordering; newly archived indices cannot retroactively prove it. Root alone schedules GPU use.

Run synthetic tests from this directory: `python -m unittest -v test_candidate`. They do not run containers or use the GPU.
