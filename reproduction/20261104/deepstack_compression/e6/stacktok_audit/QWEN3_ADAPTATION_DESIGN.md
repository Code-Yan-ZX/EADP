# StackTok on Qwen3-VL: static adaptation audit, no GPU result

This examines local author repository `e6/external_sources/stacktok_571bdc6`, clean Git commit `571bdc6c4c6b3c92a94fe2a92e3aaf42b989cc96`, Apache-2.0. It supplies LLaVA and **Qwen2.5-VL**, not Qwen3-VL, integration. A Qwen3 implementation would be a local adaptation and must not be represented as an author-released Qwen3 baseline. No Qwen3 experiment, GPU run, quality or speed claim is made here.

## Author semantics that must survive

- `stacktok/qwen/vision.py` captures the final vision hidden state **before the main merger**, averages each 4-patch merge group, applies the main merger, then reverses Qwen2.5 window ordering for both streams. `stacktok/qwen/model.py` feeds the projected image embeddings and the averaged encoder features into `StackTokCore.apply_selection_preprocess_qwen`. On Qwen3 do not copy Qwen2.5's window-reversal operation: Qwen3's source path has no Qwen2.5 `window_index` permutation.
- Qwen author injector defaults: text/visual softmax temperatures 0.01/0.2; beta 0.3–0.9; auto swap with epsilon 1e-6, one pass and `swap_auto_max_k=16`; remove padding false. Keep these unmodified for a faithful local core comparison. `retain_ratio` is converted by integer floor to `max(1,int(ratio*N))`; at fixed N=1024, 0.25 gives K256. For K128/512 use 0.125/0.5 and verify actual integer result. Do not silently tune parameters to make scores better. Core `select_vision_tokens` keeps all when K>=N; use that path for a K1024 identity control.
- The Qwen integration concatenates all user text parts, strips image markers, then core prepends `Question: `. It tokenizes `text.split()` with `is_split_into_words=True`, truncation and the actual model's input embedding table. This can include instructions and answer options; it is not guaranteed to be the bare question. Build the identical text from the E1 input message representation, record exact string/token IDs and disclose scope; empty text and stale-per-request question state must fail closed. No answer reference is needed.
- `StackTokSelector.stacktok_single` builds fp32 text-to-projected-vision and pre-merger-vision-to-vision row-softmax matrices; derives beta and a K-step visual-coverage reference; then performs gated relevance/coverage greedy K selections and optional swap. The returned IDs and projected tokens are spatially sorted; `selected_before_sort` is a separate greedy order. Preserve both and compare the actual sorted output, rather than replacing its objective with EADP's.

At fixed image resolution the input is expected `[4096,1152]`; verify real `grid_thw`, contiguous grouping, dtype, single image and merge size 2, then calculate `view(1024,4,1152).mean(dim=1)` with the author's actual dtype semantics. The Qwen3 main merger returns `[1024,4096]`; assert both token counts and alignment. This is motivated by Qwen3 `rot_pos_emb` / `fast_pos_embed_interpolate` grouping in local transformers 4.57.1 (`modeling_qwen3_vl.py`, SHA256 `685b10cbc48556343df4e159199c5884d02db9ad227640f0f4fbe75ddf0b2a99`). The existing `e4/budget_adapter.py` assumes the EADP wrapper already pruned the main feature stream; therefore it cannot simply be attached unchanged to a StackTok selection.

Before evaluation: CPU synthetic tests for group mapping, deterministic small matrices, ties/zero, K bounds, permutation and three-stream gather, no question leakage, hook cleanup and failure preservation. Same-image/no-GPU worker preflight must check exact interpreter/source/modules/weights/inputs without loading model or CUDA, and independent prelaunch review with actual container/exit records. A separately scheduled real GPU identity gate should first run K1024 keep-all vs real unmodified native Qwen3 on three frozen DEV anchors: processor/visual/three DS/prefill/position/delta/first logits/natural IDs and fixed32 decode/KV; then fixed K256 full local adapter against direct calls of the same original StackTok core, including actual embeddings/indices/three DS and original P3 positions. Include failure cases; do not use a candidate's own trace as the native oracle. Do not read GT or score until all planned natural outputs and independent acceptance complete. ## Costs and remaining blockers

For N=1024 the raw fp32 visual-similarity matrix alone is 4 MiB; text-vision matrix is T×1024 fp32 plus normalized feature and transient matrices. The original greedy reference and selection both iterate up to K, with dynamic candidate tensors, reductions and numerous `.item()` host/device synchronizations. Worst-case visual coverage work is on the order of K×N², plus matrix construction and text coverage; actual runtime and peak memory must be measured rather than inferred from token counts. Full Qwen3 visual trunk, main and three DS mergers run before selection; pre-merger hook capture and 4-patch mean introduce extra work and memory. Diagnostic cloning, synchronization and full trace must be excluded from later performance timing. No speedup or author-equivalence claim is justified yet.

The author model environment is Python 3.10.20 / torch from `_reproduction/envs/qwen_author`, but `loguru` is absent and `pytest` is absent. A direct run of the author's unchanged test entry failed on `ModuleNotFoundError: loguru`: `monitor_author_test_import001/terminal.json` is nonzero and retained. No package was installed and no external repository source was edited. A second supervised CPU-only isolated test loaded the **original** `selector.py` directly and supplied a minimal module namespace to execute the author's **unchanged** five toy test functions: `isolated_test001.json`, `monitor_isolated_test001/terminal.json` completed/0. This bypassed package/runtime imports and is not a passing package installation, Qwen text-tokenization test, real model test, CUDA test or a performance result. The missing runtime dependency and exact same-container import chain must be resolved by an explicitly reviewed environment provision or already available compatible environment before runnable model preflight; do not silently fake the logger in the research run.
