# EADP K128/256/512/1024: P3 + DeepStack natural-TTFT design

Status: source/identity/cost assessment, no new GPU run, labels, scoring or timing claim. The original quality and timing files remain unchanged. The pilot is not a full-panel timing study.

## What exists and can be reused

- The accepted E4-A full DEV panel `e4_panel_v2/panel_003` generated 384 questions × four budgets × DS on/off, natural recipe, with P3 positions; `e4_panel_v2/panel_003_verification.json` and `e1_independent_review/e4panel003_review.json` plus their actual completed supervisors are the source gates. Its 384 same-question DS-on records per budget provide already accepted raw answer tokens, processor identity, EOS, selected IDs, positions and DS summaries without reopening GT. Full panel tensors are summary-only, so the panel alone does not independently recreate per-layer high-dimensional tensors.
- The separate `e4/smoke_001_verification.json` and `e1_independent_review/e4smoke001_review.json` cover actual multi-budget multi-arm anchors including full diagnostic arrays and forced decode; `e4_native/native_001_verification.json` and `e1_independent_review/e4native001_review.json` compare K1024 DS-on with native stock on three anchors, including forced decode. Reuse their fixed inputs, proof hashes, logs and scope; do not describe 384 full-panel high-dimensional arrays as archived.
- `e4_c_latency/timer.py` timestamps the first selected token after it has been appended using a stopping criterion and one synchronization. It starts before author image read/processing. The accepted E4-C K256 lightweight identity `e1_independent_review/e4c_light_smoke003_review.json` and full timing `e1_independent_review/e4c_latency_full001_review.json` support that K256 implementation and clock boundary. `e4_c_latency/light_adapter.py` itself rejects `keep != 256`, hard-codes `delta + 768` and `mask[start:start+256]`; it cannot be reused unchanged for any requested new K. Diagnostic `e4/budget_adapter.py` supports all budgets but clones, checks, `.cpu().tolist()` and hooks tensors; it is a correctness comparator, not a latency path.
- The existing author full visual path is executed before its language-space EADP selector. For K128/256/512 the author greedy runs once. At K1024 the author's pruner bypasses greedy entirely; it is incorrect to assume `ordered` will be captured by the 256-only greedy hook. Use the accepted native/keep-all semantics and original three-stream DS handling; do not run a fake 1024-step selector or silently drop DS.

The same three DEV image-group anchors as the Pixel natural pilot—DocVQA 63709, TextVQA 39033, AI2D 11001—each have four accepted E4 DS-on natural references. Their 12 stored generations have 2–5 output tokens, all EOS, no truncation. Existing quality-panel wall time was 2312.08 s for all 3072 instrumented arms including loading, and the full E4-C K256 5940-job timing run took 6800.63 s. These observations are neither per-arm benchmarks nor safe extrapolations to K128/K512/K1024 or long-tail questions.

## Required implementation and gate

Build a new separate low-observer adapter, without modifying frozen E4 sources, for K128/256/512: preserve the actual author ordered selector and sorted spatial subset, use its `K` for selected rows, replace delta by the independently derived `full_delta + (1024-K)`, inject precisely three selected DS streams and matching mask, and preserve all text tokens/attention. Verify real `K`/quota/call count without tensor clones, hashes, device-to-host synchronizations or per-layer tracing inside the timed boundary. At K1024 add an explicit keep-all implementation that handles zero greedy calls, natural three-axis positions/delta and all DS streams; establish which native/adapter mechanism matches the accepted quality path. Do not count selection observers as free.

Before measuring, in a separate diagnostic rather than timing phase, compare each new budget path to the already accepted E4 quality or native path on the same task/qid/message/image/processor SHA and complete natural token sequence, selection/spatial IDs/quota, prefill embeddings/mask/positions, original and adjusted deltas and all three actual DS inputs; use fixed 33-token forced outputs to verify 32 decode positions and every layer KV lengths/fingerprints where captured. Include the no-greedy 1024 branch, common wrong-delta and equal-but-wrong-DS counterexamples, model setup/release and hook cleanup; retain full diagnostic arrays for anchors. Validate cache/prefill independently, not solely by comparing two arms to each other. Lock GPU until CPU contracts, actual no-GPU container preflight, complete real-model endpoint diagnostic, formal and independent review and root scheduling have passed. Bind actual module import paths, weight payload/source, preflight and reviewers; preserve failures.

## Timing plan and scope

First use 3 images × 4 budgets with all four arms randomized within each same-image block and a fixed seed, one warmup plus one measured natural generation per arm. Include K256 in the new interleaving to avoid equating it with a different run's historical baseline. All arms must use the same checkpoint, GPU, actual processor tensors, original natural generation controls, EOS and accepted same-budget 384-panel output; persist each raw generation before later processing. TTFT begins before image read and stops only after first-token selection as above; exclude model loading/setup but disclose it. The final process topology must be predeclared: either one loaded model interleaving K values with proven clean budget-state reset, or isolated per-arm processes with matching setup/cache boundaries and explicit process startup costs. Do not combine historical isolated-process Pixel values into a paired claim across runs. Record all samples and monitor health windows; when a window/time namespace is missing, mark overlap unknown. Control other GPU and heavy CPU/IO, disclose any external background.

If pilot identity and measurements pass and the user deadline/resource isolation permit, freeze a larger group-paired DEV-only schedule (e.g. 32 preselected image groups per task, or all 384 if measured costs permit). Bind all E4 panel source/output hashes and match same qid/image across K; retain same recipe and use per-image ratios or paired differences, with image-group bootstrap for a larger panel. The existing 384 quality scores can be paired only through already accepted records; do not reopen CONFIRM/FINAL or read GT for timing. Separate latency from NVML process sampling: the existing NVML chain does not automatically prove these new K configurations. Report no entire-device peak as a process peak. Freeze deadline, progress journal, GPU/host status, per-job and outer hard timeouts with stop→kill→inspect before starting. Estimate realistic wall time and long-output sensitivity using a small fully verified pilot, not K count or uncalibrated old diagnostic elapsed times.
