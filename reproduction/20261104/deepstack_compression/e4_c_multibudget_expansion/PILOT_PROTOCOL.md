# 四预算、32图性能 pilot：样本合同与实现边界

这是观察过此前 DEV 和性能之后制定的探索性 pilot。清单 `pilot_plan001.json` SHA256 `94b8a159f4a787b541b9f41b27a62921e3a8a6a0b44ff648d8d35d46d5725f7f`；其生成进程 `monitor_freeze001` completed/0；纯CPU合同测试 `monitor_cpu001` completed/0。清单只读取已验收的64图时延面板样本表及 E1 的无答案输入，未解析预测或GT，不读取/启动GPU。计划含此前已观察样本，不能称全新盲态验证。

## 清单

从已验收 E4-C 原每任务 64 个计量图像组分别以 `SHA256('20261105|e4c-four-k-pilot-v1|pilot|task|group_id')` 排序，取 Doc 11、Text 11、AI2D 10；每任务沿用原计划与测量64组互斥的10个预热图。清单 `input_identities` 记录62条输入的 task/qid/group、图像路径/SHA 和 message SHA，关联到已验 E1 输入工件；正式运行应重算真实图、处理器和消息身份，清单并不自行验证磁盘图像或执行 processor。`cohort` 记录每任务的 measured/warmup 组；`jobs` 固定240个预热与1280个计量，后者为32图×5次×4K×自然/fixed32。每一重复/同图的8个预算×协议排列依据同一冻结 seed 的SHA顺序确定，全部预热在测量之前。这个顺序用于试运行，不能在看到结果后重排挑选。

`gate.check_plan` 是CPU规划检查：复核来源SHA、固定用户截止、外层时间+验收余量及工作量；`gate.require_gpu()` **恒拒绝**，因为实际多预算固定长度 worker、模型身份证明、真实无GPU前检及最终独立审查尚不存在。它不是可运行GPU launcher，也不授予GPU权限。若计划或任何受绑来源变化，应另编号重冻和复审。

## 相对 v3 的实际变化

| 项目 | 已有 v3 | 本 pilot 仍需新实现 |
| --- | --- | --- |
| 样本与顺序 | 3图、每K 3次、自然生成；12预热+36测量 | 32测量图、每K每协议5次，另30图×8臂预热；按上述完整8臂同图块和固定hash排序 |
| 输出协议 | 仅自然 greedy，逐题与已验E4同预算自然记录核对 | 保留自然控制与原E4身份；新增 min_new_tokens=max_new_tokens=32、EOS约束与实际序列留存；固定长度不评分 |
| 完成边界 | 先 fsync 输出再计 completion，因此 completion 含日志写盘 | 完整生成返回并完成约定同步后立即记完成时间，再持久化全部原始IDs；记录任一步失败，不能只报通过案例 |
| 真实身份 | 多预算诊断及三锚、K1024 native 对照 | 新轻量路径与原诊断路径分开对照；新K/任务固定32、位置、三DS和逐步KV另验；已有全量哈希不能当逐元素张量证据 |
| 资源及外部条件 | 三图短运行与独立的宿主快照 | 独占GPU、硬超时+停滞门和真实退出链、图组重复、外部Java与健康采样窗口和未知背景；统计不移除被扰动样本 |

## 固定32与事后验收

固定32自然贪心延长通过 min=max=32 禁止提前 EOS；生成32个token一般对应 prefill 加31次decode。它不能代替另外指定的**33输出/32 decode**身份诊断；后者应在多任务预定锚和各K上记录输入、原预算选择与有序位置、真实prefill/mask/三DS、每步三轴位置、cache_position/rope_delta、全部层KV长度/指纹与输出，和真实诊断参考逐项比较。对K1024另保持零greedy与native keep-all控制。K256若要绑定已验E4-C固定32结果，应先确认题组、模型输入、生成设定、EOS/前缀、源和实际输出一致；其余K无同协议既验完整引用时，应先生成独立诊断参考并保留差异，不得把E4自然答案作为固定32的参考。

运行前对62个输入逐项验证来源、各job清单、warmup与measured互不重叠和所有8臂均出现；合成反例覆盖错误K/顺序/重复、提前EOS/短32、错误位置信息、KV步骤重复或跳步、DS错序、首token/完成边界、来源替换、失败后停止与原始输出留存。完成后验收必须先确认监督和容器真实退出，再按1520个预定job逐一重核身份与原始结果、输出token及长度协议、计时边界和完整日志；自然答案比既验E4同题同预算，固定32比较经审查的同协议参考；统计按图像组保留5次重复，不移除无效/受干扰项，任何缺口明确标记不可用和全分母。

模型与计时 worker/launcher 由 infra 在独立目录实现；其需要将本清单、源SHA和既有身份门纳入自己的完整审批链。GPU只能由主控协调，当前无GPU可执行授权。若要从这32图扩充到每任务64图，后续面板不得自动复用 pilot：只有运行前明确并实际保持同一源/协议/调度、预热、身份与完整记录时，才可按先定规则处理；否则32图单独报告。
