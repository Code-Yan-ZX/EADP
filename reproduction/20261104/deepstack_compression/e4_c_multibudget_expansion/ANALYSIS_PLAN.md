# 四预算 32 图 pilot 的预定分析口径

本计划在 pilot 生成/计时结果读取之前制定；样本和扩面决定是在既往 DEV 与计时结果观察后制定，属于事后探索。使用已冻结 `pilot_plan001.json`（SHA256 `94b8a159f4a787b541b9f41b27a62921e3a8a6a0b44ff648d8d35d46d5725f7f`）的32个测量图：DocVQA 11、TextVQA 11、AI2D 10；30个不同图像组和240个预热job只用于热身，不进入结果。每图每预算K∈{128,256,512,1024}、每协议（自然greedy、fixed32）各5个计时，所有预定1,280个测量job均保留；必须先通过完整生成、真实退出和正式/独立身份验收，禁止根据部分结果调整分析或选择样本。任何失败、缺失、无效计时均完整保留并列出原因，严禁仅对成功案例称完整pilot；不完整时不发布原定完整样本汇总。

## 度量和单位

按最终冻结并经验收的实际时间戳，逐job记录从开始读取原图前、经预处理和模型调用，到首个选定token的TTFT；记录从同一起点到 generate 返回后的生成完成同步边界的生成完成时间，统一转换毫秒。身份验证、持久化写盘、监控采样不得隐含进入比较；若实际边界与此不同，在分析前作为不一致留证，不能把不同边界合并。自然协议的生成完成时间包含随题变化的自然输出长度，记录每题每次token数/EOS/截断并解释这一影响；fixed32为32个输出token、31次decode forward，保留EOS设定和全部token。首token时间不是首个logit时间，生成完成时间不包括原始token复制/fsync及作者文本解码，不是完整用户端到端时延或持续稳定态吞吐。

对于每个任务、协议、预算，先对**同一图**的5次各取一次中位数，再在图像层报告该图内中位数的中位数、最小值、最大值与实际图数；对TTFT及生成完成时间分别报告。自然和fixed32分开报告；不把5次重复当成5张独立图片，也不把三任务不加说明混合为总体结论。固定输出协议的质量与真实TTFT独立，不据此推断准确率收益。

## 同图预算对照与不确定性

以K256为对照，分别在每图、每协议上，以5次TTFT中位数构造 `K − K256` 毫秒差与 `K / K256` 比值；生成完成时间同理。分任务/协议/预算汇总这两个逐图差与比值的中位数及最小、最大，并报告配对图像组数。比较基于每图各自5次中位数；不把不同预算的随机次序第r次硬配成同步重复，不把比值转成跨样本的吞吐结论。

每个任务和协议内，以图像group为单位做有放回配对重采样10,000次，种子20261105，group_id按字符串升序后使用 NumPy 2.2.6 的 `default_rng`；同一重采样索引同时取该组所有预算。对每个预算的中位时间、同图差的中位数以及同图比值的中位数分别计算2.5%/97.5%百分位区间。报告每任务图像组数、NumPy版本和样本来源；若实际版本不是2.2.6，先冻结新的版本与测试再分析；此小样区间仅描述样本与重采样变化，不能证明显著性，不做多重比较校正，不外推全部任务或生产环境。若某任务发现group重复，组内按问题数先计算组级均值后再按组抽样，并在执行前锁定对应源码与验收；当前预定清单应逐项验证group互异。

## 干扰及完整性

保留所有预定观察，不因结果大小、宿主Java活动、后台采样或运行时抖动删除。逐job依据可对齐的单调时钟、时间命名空间记录已知GPU/CPU/进程/Java/磁盘/采样器活动与监控窗口；无法定位到样本的轻量活动标记为未知而不推断无影响。完整报告原始时间、预热和随机交错顺序、容器/监督/输出身份及可用的显存口径，并单列干扰范围；需要分析敏感性时作为附加后验分析、同时保留主结果。任何设备占用、监控缺口、源码或输出身份不符均按冻结验收门处理，不能事后只排除异常样本。

本计划是统计口径草案，仍需由独立审查确认绑定正式worker、所记时间字段、5次顺序、输入清单、完整验证proof、环境/NumPy版本及可执行合成反例；这些尚未闭合时不可报告正式结果或启动GPU。它不将32图称为用户原要求的每任务64图完整实验；后续扩面须单独冻结并明确是否满足同协议的逐题复用条件。
