# Pixel natural TTFT pilot: implementation status and intended bounds

This version prepares a proof-gated GPU launch plan for independent review. Its actual code has a CPU-tested natural Pixel and EADP call path, raw per-call output durability, a lightweight selector-return K observer, warmup with this observer disabled and measured call with it enabled, per-call comparison to accepted same-arm tokens/EOS/K, post-generation actual processor verification, and PyTorch allocator baseline/peak bookkeeping. It has a CPU-fake subprocess isolation rehearsal. The real Docker controller and model entry require a matching independent prelaunch proof and fail closed while that proof is absent; the CPU-fake controller is not GPU evidence. A real-container/no-GPU controller-worker release handshake remains to be tested. Actual observer-on/off equality is still untested on the GPU. Neither `cpu001.json` nor any no-GPU preflight constitutes a GPU prelaunch approval.

The frozen v3 DESIGN describes the earlier design stage and is superseded by this implementation status. Its separate memory-sampling proposal is not implemented. The planned immediate experiment is TTFT plus PyTorch allocator exploratory measurements in the same fresh worker. Allocator statistics cover entire generation and exclude non-PyTorch allocations; they are not NVML process usage or an entire-device peak. A future genuine memory phase requires a separately reviewed real NVML worker/PID handshake and sampling protocol. No total-device/graphics memory value may be presented as exclusive process peak.

Prepared real GPU controller: 9 single-model container processes, one for each seeded paired job; one warmup and one measured natural call in each. Serial, no overlapping GPU jobs. Each container has its own process identity and a hard 1200-second limit measured from launch, with explicit TERM/stop, then kill if needed, and final Docker inspect and retained exit/error evidence; a timeout or any missing identity/exit/expected output fails the run. The controller is itself supervised with a proposed outer hard limit of 11700 seconds (9×1200 plus 900 seconds for control overhead), and at least 120 seconds' termination grace. Do not silently restart or overwrite partially completed attempts. Before admission, `initial_plan.json` and actual wall time must prove the entire outer limit plus grace fits the user's three-day deadline; otherwise refuse. The fixed three anchors have 2–5 natural output tokens in accepted reference runs. On this host, the prior threshold .45 full 384-question diagnostic including model startup took 540.22 seconds, threshold 0 full diagnostic took 225.23 seconds, and the 36-call EADP scatter TTFT run took 105.28 seconds; these are context, not worst-case guarantees. A 1200-second limit for each warmup+measurement job retains substantial margin and stops rather than retrying or dropping an unexpectedly slow job. These bounds are planning caps, not runtime guarantees, and require final root scheduling.

The timing-aware supervisor must record hourly health-call monotonic windows in the same clock namespace; preserve all 9 measured samples and flag overlapping windows, while disclosing background operations with no precise timestamps. Before every job check no other GPU compute process; this snapshot cannot by itself establish that none appeared during the job. Docker/container/GPU identity, actual entrypoint/environment/mounts, output job identity, single-use process, evidence hashes, and clean exit must be bound by the final launcher/verifier and independent reviewer. Separate model-load, warmup and capture/setup from TTFT; processor and image read must be inside TTFT, no per-layer clone/hash, and the first-token timestamp must follow token selection. Prior accepted quality results establish references, not speed. Report raw results for 3 task anchors and conditions, no broad speed or quality conclusion.
