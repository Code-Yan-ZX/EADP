# NeXT native AnyRes formula-to-quota diagnostic — preparation only

The question is whether two concrete formula differences propagate through NeXT's five-crop quota rounding into actual retained visual positions. The POPE single-crop16-image result did not test this mediator. No benchmark answers, GT labels, scoring or new hyperparameter selection are used here. This directory prepares a future diagnostic; it does not allocate GPU or start a worker.

The16 questions are fixed at positions2,6,10,...,62 in the previously registered64-question source-equivalence panel. They are selected by that position rule alone; all16 image basenames must be unique. Questions and image hashes are frozen before execution. This is a new16-position subselection of the existing fixed64 panel, not an assertion that a16-NeXT panel was previously run. Existing NeXT numeric-cache inspection found no native projected features, visual similarity matrices or quotas that can replace feature extraction; vendor-package `.pth` bootstrap files are not tensor caches.

Only five already-complete actual recipes are included: alpha.5/beta2 with CLI128/64/32 and alpha.5/beta1 with CLI128/32. No beta1/CLI64 is added. Four cases per recipe are fixed: original source, unchanged source-members/order identity, Eq6 quantile-membership only and Eq10 numerator-epsilon only. This gives16×5×4=320 planned case slots, not a budget/parameter grid selected by answers or scores.

Future execution uses the fresh author native builder, the exact previously declared three waits, SDPA, and the released NeXT checkpoint including its embedded vision body. Its runtime must match the completed full-default audit: vision bodyFP16, visual projectionFP32, text towerFP32, mm_projectorFP16, defaultFP32, no autocast and matmulTF32 false. The public base CLIP vision body is never substituted. Native AnyRes input is1×5×3×336×336; its original flattening creates5 crops with split_sizes=[5]. The native alpha.5/beta1/CLI128 encode path runs once per image and is the mandatory source anchor for importance, internal IDs, quotas and final source mask.

Every recipe/variant reuses the same real GPU projected features, cross-modal similarities and native visual facility matrix. The source importance AST is retained from filtering through beta power. Its global min/max reshape is1×2880 before restoring5×576; normalizing each crop independently is forbidden and explicitly rejected by a CPU fixture. Original source helpers and greedy code remain unchanged. The final mask is also compiled from the exact original source mask AST.

Eq10 removes only numerator1e-6; all denominator ASTs remain identical. Eq6 computes linear q=.2 entropy quantiles for each actual crop/segment row, retains all ties at or below threshold, keeps the original top15 order intact and appends new members in original token-position order. If every crop/segment row has the same new length, the original rectangular batch gather and original batch local_aggregation are used. If those lengths differ, that image's Eq6 cases are explicitly recorded as unmeasured_ragged_quantile, with full threshold/member tables; there is no silent padding, flattening, rowwise aggregation, alternative formula or automatic retry. Original/source-identity/Eq10 cases continue. A summary with any such gaps is complete_with_unmeasured_ragged_eq6 and reports measured versus planned case counts separately; it cannot claim320 fully measured cases. All native arrays are preserved for later review without reloading a model.

The source-members/order identity must yield exact importance, quotas, all gain vectors, IDs and masks. Every traced greedy call must agree exactly with a separate unchanged original call; its only source-AST observer appends detached gain clones. Trace overhead changes timing, so no efficiency result is taken from it. Source baselines repeat at the end of each recipe block to detect unstable replay. All captured and derived numeric tensors must be finite. Frozen source, implementation, reference, model stats and16 image hashes are checked again before terminal success.

Each crop's greedy loop runs to the image's max_T, but only the first quota[crop] choices are valid. The report separates internal max_T sequence changes from effective prefix changes, integer quota changes, retained spatial IDs and the actual final mask. Changes confined to the discarded suffix are never called model-input changes. Quota-driven prefix-length changes and actual added/removed tokens are explicit. For shared-prefix greedy divergences, the first effective competing picks and their recorded gains under both maps are retained. The report does not reinterpret changes after a differing prefix as the first causal flip.

`diagnose_anyres.py` defaults to CPU-only guards and does not import torch. `cpu_acceptance.py` uses clearly synthetic CPU FP32 fixtures only; it loads no model and extracts no real features. The future GPU entry requires a separate root allocation-note with exact planSHA/runID/slot/allowed-other-PID list, fewer than two actual live GPU processes, and the frozen interpreter. Its output directory is single-attempt and partial/failure artifacts are retained. No supervisor or GPU queue exists. Actual full-benchmark accuracy and the unpublished main-table recipe remain outside this diagnostic's conclusions.
