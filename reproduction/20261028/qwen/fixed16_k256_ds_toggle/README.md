# Fixed16 K256 native DeepStack pair

This is a diagnostic of the public Qwen3-VL EADP K256 implementation, not a paper result or a new pruning method. In a single original model instance, the off arm calls the unmodified author legacy generation and the on arm independently repeats that call with only the three same-tower DeepStack rows and compacted visual mask injected into the actual first LLM prefill. The actual author greedy return is observed once and returned unchanged; its own spatial sort determines all 256 rows. The on arm requires byte-equal actual selection, processor tensors, visual/nonvisual input embeddings, attention, original prefill position/cache and rope to the off arm. It does not directly modify KV, although the intervention naturally changes later KV.

Every actual response is saved before observation or anchor checks. All 16 off answers must first match the completed FA2 K256 historical literal answers, and each actual selection/features/input must match the separately completed fixed16 K256 selection caches and K1024 visual/three DeepStack caches. Only after the full 16-anchor gate can any on arm start. Both arms' complete output IDs, actual tensor archives, continuation and failures are retained. An independent no-GPU verifier reloads and re-decodes all 32 outputs, checks byte-level row selection and the two prefill fields, compares continuation states only across common generated prefixes, and must pass after the original container exits. A separate root process proof is required after the controller itself exits.

The old K256 full benchmark did not preserve per-question output token IDs or prefill state; its only generation anchor is literal response text. Old fixed16 K256 data did not perform generation or DeepStack injection. The saved tensor archives contain the new actual tensors, not historical values substituted for new observations. The old completed prediction audit contains historic scoring fields; they are not used to choose samples or tune settings. This diagnostic reads no ground truth and performs no scoring. Runtime instrumentation makes timing unsuitable for performance claims.

CPU preflight and synthetic torch tests are required against the final frozen plan. The original sources and historical artifacts remain unchanged, and each execution requires an explicit root allocation, one model at most, and no automatic retry or queue. Preparation does not start the model or GPU. Real execution remains subject to root and independent code review.
