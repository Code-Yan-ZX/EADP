# Full DocVQA K256 paired DeepStack diagnostic — CPU preparation

One original author EADP K256/.5/2 model, one fixed answer-free 5349-row input manifest and two independent native method calls per item. The second call receives only the actual visual mask and three same-tower DeepStack tensors indexed by that invocation's real author-selected, spatial-sorted 256 rows, and only at the first prefill. Actual selection, processor input, visual and nonvisual embedding, position/cache/rope state and generation kwargs must match the first invocation. This is a conditional legacy-position implementation diagnostic, not the paper main-table result or a new pruning method. Changing DeepStack naturally changes subsequent KV and output; continuation is compared only over common generated prefixes.

All 16 original fixed-panel native off calls run first, then their 16 on calls; their actual arrays and token IDs must reproduce the completed K256 fixed16 off/on evidence before any other sample. Old fixed16 source evidence and original actual exit proof are frozen, with no access to its historical scoring data. Remaining 5333 questions are processed as sequential off/on pairs. Each actual native response is flushed first; even if observation or paired validation later fails, preserve the raw response and error. Record all output token IDs, original native answer, EOS/truncation status, processor IDs, mask, real author ordered/sorted selection, actual generation parameters, prefill and continuation observations. Do not inspect ground truth or call an evaluator during this preparation or generation.

High-dimensional arrays for the 32 fixed16 runs remain fully archived and compared byte-for-byte with prior fixed16 records. Other rows retain actual captured tensor dtype/shape/SHA-256 and selected integer IDs, not the high-dimensional tensors themselves. Byte checks in the worker use the actual two tensors before intervention; the independent terminal verifier can compare their recorded hashes but cannot independently reconstruct unarchived values or prove their actual contents anew. Old full K256 generation did not save per-question internals; its historic internal anchor applies only to fixed16, and no score or historic labeled file is read by this candidate.

Measured cost from the completed fixed16 K256 diagnostic: 32 full NPZ files total 1.44 GiB, and extrapolation of that archival style is about 481.6 GiB for 5349 pairs. From first to last saved answer, 32 generations took about 4m24s including large snapshots/compression; naive linear extrapolation is about 25 hours, excluding loading and terminal work. These estimates are highly uncertain and are not performance benchmarks. The proposed summary storage retains fixed16 NPZs and avoids about 480 GiB of other archives; high-dimensional capture/CPU transfer and true byte comparisons still add runtime. Input images require approximately 1286 distinct file hashes; answer-free inputs have 5349 rows.

The remaining work requires frozen source/model/input and process identities, no-device author-runtime tests, a terminal verifier independently reloading outputs and 32 archived anchors, and root exit proof. Do not start a model, GPU, queue or score until root and independent review have approved the completed candidate.

After both complete 5349-row streams exist, `reorder.py` preserves the original generated records and writes separately ordered prediction and observation JSONL in input-manifest order. Position uniqueness, sample ID and arm are checked during reorder; the independent verifier checks those files are exact permutations and binds the hashes of all eight original/ordered files. `score_terminal.py` is a separate, non-automatic CPU entry point: it requires both arms, all anchors, independent verification, original process/container exit and the root-owned PTY actual-exit proof before its first ground-truth-byte access. Only then may it invoke the original DocVQA evaluator and independent ANLS. The GT file's expected digest is copied from an earlier frozen plan without reading the GT during this preparation; no scoring has been run.
