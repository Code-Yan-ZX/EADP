# MMB full guidance comparison — CPU-only candidate design

Status: design under construction. No model, GPU, score or automatic queue is started by this document. Existing sources and the completed 60-row panel are not modified.

A fixed local MMB source-control test on 16 complete circular groups (60 rows) saved both original and question-only actual model runs. All 60 masks differed and one output text differed; these are mechanism-panel findings and are not a full-benchmark estimate. The alternative changes hint/option content and text segmentation together and is an inactive source comment; neither its origin nor paper table arguments are established.

## Proposed run and evidence

- Lock model files, author source, existing three CUDA wait statements, the sanitized 4,377-row inputs and independently reconstructed CPU input fingerprints, all 120 previous fixed-panel NPZ/record/raw archives, old root exit proof and accepted independent verification. No previous panel outputs are used as answers for new predictions.
- Load one LLaVA model. First rerun the 60 source and 60 question-only panel rows. After saving each native output, independently read the matching previous archive and compare all captured real arrays byte-for-byte plus output IDs and decoded text. Stop on any mismatch; do not relax the anchor or retry automatically. Preserve failure artifacts. No remaining benchmark rows may run before all 120 anchors pass.
- Then process the other 4,317 rows in the original dataset order. For each row, invoke source and question-only sequentially on the same model instance. Exact source `eval_model` is compiled in memory from locked original code; the sole variant AST replacement is the late CLIP `texts` assignment. To call the original entry for a single row, its module-local pandas reader is provided a copy of the corresponding row from the already-read sanitized DataFrame. This input-dispatch adaptation, panel-first order and same cached model loader are declared explicitly. Full LLM prompt, image, selection, generation parameters, author source, and stream-wait control remain otherwise unchanged. Successful outputs are recorded in raw execution order and separately reordered to original 4,377 row order and unique IDs.
- Before observation checks, persist the native output token IDs and decoded text or a structured failure. For every call save actual generated token IDs/text, LLM IDs, CLIP token/mask segments, selected indices in native greedy order, quota, final spatial mask, actual parameters, and metadata (shape/dtype/byte SHA) for the real pixels, vision features, text features, similarities, importance and prepared embeddings. For non-anchor rows compute selected visual rows and prepared visual/nonvisual segment hashes directly from actual captured tensors after native output is saved; cross-arm compare actual image, projected features, visual similarity, LLM IDs and nonvisual segments. Full arrays are saved only for anchors: for other rows the independently reloaded verifier can check stored IDs, masks and SHA relationships, but cannot independently reconstruct high-dimensional contents from hashes.
- On worker failure preserve the already-returned native result and errors, stop without retry and do not score. On success require real worker exit and disappearance of its GPU PID; independently validate all records and CPU re-decode outputs in a device-free container. Root must observe the actual controller exit and record a separate terminal proof. These gates precede any scoring.
- A separate manually invoked CPU scoring stage may read GT only after both full 4,377-row predictions, their verification, original process/container exit and root proof have been checked and linked by SHA. Use the author's available VLMEvalKit exact-matching helpers and a separately implemented local circular-group comparison. Retain row/group decisions, mismatches, unresolved answers, and official-helper source identity. An external official server/judge is not run and no equivalence to it may be claimed. No score is computed during preparation or generation.

## Data boundary

Do not read the answer column, GT file or accuracy artifacts while preparing inputs or generation. Source full prompts and options are preserved by the prior native prediction files. A read-only CPU check has uniquely recovered question-only texts for all 4,377 by matching previously frozen text hashes against suffixes of those source prompts. Image bytes must come from an independently available GT-free source or an explicitly documented sanitized extraction authorized by the root; image-hash manifests alone are not images. Input preparation must report the exact source and whether GT-containing bytes were physically read, not conflate `usecols` with avoiding such reads.

## Resource evidence

Previous source 60 native generate calls took 10.24 s total; variant 60 took 8.96 s. A crude linear extrapolation gives approximately 1,401 s (23.4 min) for 8,754 native calls alone, excluding model loading, capture, host copies, hashing, validation and scoring; 60 is a small/nonrepresentative sample. Worker start through verifier start for the old 120-call panel was about 282 s, including model load and compressing all full arrays; mechanically multiplying by 8,754/120 gives about 5.7 h, not a predicted runtime for the new design because only 120 new anchors retain full NPZs. Actual runtime and GPU peak are unknown. Prior 120 captures and associated files occupy approximately 1.1 GiB; this new design needs at least a comparable anchor footprint plus full sanitized data, token and record files. Disk free space was 1.1 TiB when checked but must be checked again at any eventual allocation.
