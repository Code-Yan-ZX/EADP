# MMB question-only guidance: fixed16-group diagnostic design

This is a CPU design and source-boundary proof, not a launch plan or an executed comparison. It proposes one LLaVA-v1.5-7B author model instance, original MMB EN20230712 inputs, K128/alpha .5/beta 1/q .2, the same accepted three-wait CLIP runtime, FP16, vicuna_v1, greedy max_new_tokens=1024 and one source and one question-only call per fixed row. This tests an inactive public-source alternative; it does not establish the paper's unpublished argv or an implementation error.

The panel is fixed in advance from all 1176 sorted original base group IDs using `floor((2*i+1)*1176/32)` for i=0..15, taking every pre-expanded rotation. The 16 base IDs are 72, 217, 370, 498, 632, 767, 909, 1030, 1143, 1255, 1364, 1480, 1591, 1706, 1821 and 1936. Fourteen groups have four rows and two have two, giving exactly 60 source and 60 alternative generations. Existing dataset records are already rotated: preserve the previous `all_rounds=false` and `round_id=0`; enabling an additional loop would duplicate rotations.

The sole tested source input difference is the inactive alternative immediately after the complete LLM conversation prompt is built: replace `question = cur_prompt` with `question = row['question']`, before `texts=question` is passed to `generate`. This removes options and, for rows that have them, hints from CLIP guidance. It preserves the full hint/options LLM input, source output `cur_prompt`, option characters, images, model, existing three-wait patch and generation settings. A reversible AST transform must prove the entire untouched `eval_model` is recovered when that assignment is reversed. Execute the actual edited code identity under the correct source/filename guard, without modifying author files, and maintain the same three-wait behavior in both arms. Capturing source or hook failures must not alter native control flow.

Before any alternative call, generate and save all 60 original-guidance responses. Validate each against its corresponding completed source text and accepted question ID, current source prompt/guidance SHA, original LLM token IDs/hash, decoded image identity and actual FP16 processed pixel SHA. Preserve all native outputs before judging anchor or observer errors. Historical results did not preserve selector masks, importance, embeddings or output token IDs: those quantities can only be compared between the two newly observed arms, never labeled as historical byte anchors. A missing or differing source text is preserved and stops the alternative arm, without retry or filtering.

For both arms capture actual CLIP input text/token IDs/attention/segment counts, current image and projected visual features, CLIP vision/text embeddings, native visual/global/local similarity and importance, true greedy return/quotas, final boolean mask and retained spatial visual inputs, original and final multimodal embeddings, actual nonvisual prefix/suffix and LLM input/output token IDs. Verify complete LLM prompts, source token IDs, image tensors, image features and nonvisual input regions remain byte-equal; only guidance-sensitive pruning and its downstream visual sequence may differ. Save actual responses first, then actual captured arrays and errors. Independent CPU terminal verification must reopen all 120 outputs and arrays, independently decode output IDs, cross-check source guidance and sample IDs, confirm the true masks/selected visual rows and compare same-condition prefixes, then verify the original process/container and controller actually exited. Circular rotations deliberately change option letters, so group members must not be required to return the same letter. This combined semantic/segmentation intervention is not a pure length control. No GT scoring, result-direction gate, parameter search, retry or automatic full-dataset expansion is part of this panel.

The input-only native tokenizer audit covers all4377 pre-expanded rows and 1176 groups. On the 60 fixed rows, original CLIP guidance lengths are19–172 tokens, 8 exceed77 and use multiple segments; question-only guidance is at most29 tokens and single segment. All60 token signatures change. All 60 prior source `texts` hashes, input token counts, image FP16 shapes/sizes and literal response records were independently matched. This only shows that inputs and historical texts are available, not that any mask or accuracy changes.

The completed prior matching source run measured 60 selected source `generate` calls totalling15.98 seconds, median .283 seconds; doubling gives ~32 seconds of historical GPU calls for 120, excluding model loading, observation, tensor transfer/archive, source replay, validation and possible longer alternative answers. Actual elapsed time and GPU peak memory are unknown and need measurement; this is not an efficiency benchmark. A 576×4096 FP16 projected visual matrix alone is 4.5 MiB per arm/row (~540 MiB for120); full capture, extra similarity/CLIP/LLM tensors and archival overhead require more space and time. Reserve adequate disk and a single isolated model allocation only after root reviews a complete independently tested plan.

Reading an original TSV file or hashing its bytes can physically read bytes containing the `answer` field even if a parser uses `usecols` to exclude it. Any future sanitized panel preparation should accurately distinguish byte-level source reading from parsing/using GT: exclude GT columns from the runtime panel, never score or select samples by the answer, and do not claim the original answer-bearing TSV bytes were never accessed. No GPU/model or scoring is used by this design; no executor or queue is provided.
