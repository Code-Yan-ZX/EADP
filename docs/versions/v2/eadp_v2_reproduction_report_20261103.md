# EADP 复现与 DeepStack 实验汇报

汇报日期：2026 年 11 月 3 日  
范围：本次对话中完成的论文数据整理、本机复现、原因排查和 DeepStack 实验。

## 一、目前可以得出的结论

1. **原公开配置的复现仍有差距。** 对 MMB、POPE、LLaVA-NeXT TextVQA 及 Qwen3 的 DocVQA、AI2D 等七个重点设置，已完成全量复现或历史结果核验；在已核查的公开配置下，本机结果均未达到论文相应数值。
2. **差距不能简单归因于同一个问题。** 排查发现生成同步、输入指导内容、模型生成路径和评测方式等都可能影响结果；论文主表的完整运行参数没有从公开材料中唯一确认。
3. **DeepStack 对本机 Qwen3 DocVQA 影响明显。** 同一模型、同一批 5,349 题及相同 EADP 视觉 token 选择下，接入 DeepStack 后，ANLS 从 **61.1660 提高到 67.9031**，提高 **6.7371 个百分点**。这是修改公开实现后的本机诊断结果，不是已证实的论文主表配置。
4. **已保存开启版的性能基线。** 单张 A40 上，开启版自然生成平均 **0.705 秒/题**，PyTorch 已分配显存峰值最高约 **16.70 GiB**。16 题、固定输出长度的小样本中，开启平均比关闭多约 **4 毫秒/题**，差值小于测量波动。

## 二、目标和数据来源

本阶段的目标是先弄清楚 EADP 论文能否在本机复现，再根据可靠实验寻找改进方向。推理阶段仍以可部署的视觉 token 剪枝为目标，最终方法由实验结果决定。

数据只采用两类：**EADP 论文实际报告的数值**，以及**能追溯原始预测、评分和运行记录等证据的本机实验数值**。此前直接转述但没有对应实验记录的数据未纳入结果表。

最初对照整理了论文三张主表共 **99 个 EADP 数值格**，其中 **29 个格子**找到可追溯的本机历史结果。剩余格子在本次来源清单中没有足够证据，并不等于证明本机从未运行过。附录列出全部 99 格；不同历史实验的模型、预算、参数或运行环境可能不同，不能把逐格结果拼成一次统一运行的平均分。

以下列出系统排查台账中的 **12 次完整新运行**。每行都是独立运行或独立控制，不从中挑选最高值替代原结果。除 MMB 问题行和 POPE 题数外，NeXT TextVQA 为 5,000 题、DocVQA 为 5,349 题、AI2D 为 3,088 题。

| 模型 / 任务 | 预算及实验设置 | 论文 | 本机 | 本机 − 论文 |
|---|---|---:|---:|---:|
| LLaVA-1.5 / MMB-EN | K128，公开代码原路径 | 62.7000 | 61.5646 | −1.1354 |
| LLaVA-1.5 / MMB-EN | K128，仅增加三处等待同步 | 62.7000 | 61.5646 | −1.1354 |
| LLaVA-1.5 / POPE | K32，α=1、β=1，原路径 | 86.7000 | 77.3937 | −9.3063 |
| LLaVA-1.5 / POPE | K32，α=1、β=1，三处等待同步 | 86.7000 | 82.2202 | −4.4798 |
| LLaVA-NeXT / TextVQA | 名义 K640，α=0.5、β=1，完整 OCR 指导 | 59.2000 | 56.9440 | −2.2560 |
| LLaVA-1.5 / POPE | K32，α=0.5、β=1，三处等待同步 | 86.7000 | 82.7060 | −3.9940 |
| LLaVA-1.5 / MMB-EN | K128，α=0.5、β=2，三处等待同步 | 62.7000 | 61.3946 | −1.3054 |
| Qwen3-VL / DocVQA | K256，公开 EADP 路径、FA2/BF16 | 62.8000 | 61.1660 | −1.6340 |

| LLaVA-NeXT / TextVQA | 名义 K320，仅选择指导改为问题 | 57.0000 | 54.9580 | −2.0420 |

POPE 的三处等待同步使公开原路径从 77.3937 变为 82.2202，同时检测到的 2,334 组重复输入中互相冲突的回答从 231 组降为 0 组。进一步将 β 设为 2 得到 84.2789；这属于固定参数控制，**不能据此认定论文使用了该参数或证明全部差距已经解决**。

NeXT 的 K320 问题指导控制从 54.9000 变为 54.9580，仅增加 0.0580 点；语言模型仍收到完整 OCR 提示。该实验验证了一个输入假设，不能认定为论文原配方。

完整记录见[12 次全量运行台账](../../../reproduction/20261028/full_run_ledger_v4.json)。

## 五、不剪枝基线与其他排查

不剪枝的完整视觉 token 基线用于判断：差距是否只出现在剪枝后。它们不是 EADP 剪枝结果。

| 模型 / 任务 | 论文不剪枝 | 本机不剪枝 | 说明 |
|---|---:|---:|---|
| LLaVA-1.5 / POPE | 85.9000 | 85.8787 | 按论文一位小数精度同为 85.9 |
| LLaVA-1.5 / MMB-EN | 64.7000 | 64.3707 | 4,377 行 / 1,176 组 |
| LLaVA-NeXT / TextVQA | 60.3000 | 60.3700 | 5,000 题；本机按一位小数为 60.4 |
| Qwen3-VL / DocVQA | 94.5000 | 94.4816 | 本机同环境原生多模态路径 |

Qwen3 进一步比较了两条**都保留全部 1,024 个视觉 token**的路径：原生完整路径得分 **94.4816**，经过 EADP 生成入口但不剪枝的路径为 **87.8254**，相差 **−6.6562 点**。两条路径除了 DeepStack 之外还有位置等差异，因此不能把全部差距都归因于 DeepStack；K1024 也是机制诊断，不是论文 K256 剪枝结果。

在两条完整路径内分别开关 DeepStack：原生路径开启到关闭为 **94.4816 → 92.3855**；EADP K1024 路径关闭到开启为 **87.8254 → 91.3101**。这些结果说明特征传递会影响完整路径的表现，但不能直接替代 K256 实验。

MMB 还做了选择指导文本对照：EADP 使用原完整指导时为 **61.5646**，仅改为问题指导时为 **62.1599**，增加 **0.5952 点**；4,377 行 / 1,176 组全部完成。这是修改指导输入后的本机机制实验，未运行外部官方服务器，不能认定为论文实际配置。

另外，对 POPE、NeXT 和 Qwen3 的剪枝公式及候选选择做过固定 16 题 / 图像的机制检查。多数受检微小公式变化没有改变最终选中的 token；NeXT 的一个设置有 1 张图的最终选择变化。小样本只能说明受检条件下的现象，不能证明所有数据都不受影响，也不能替代全量准确率结果。

## 六、DeepStack 开关实验

### 6.1 为什么做这个实验

Qwen3-VL 的视觉编码器会产生多层 DeepStack 视觉特征。核查作者当前公开代码发现：EADP 的 Qwen3 剪枝路径没有将这些特征继续传给语言模型。我们在公开 EADP 实现上做了受控修改，将 DeepStack 特征按实际选出的 256 个视觉 token 位置传入，保持其余对照条件一致。

### 6.2 DocVQA 全量效果

设置为 Qwen3-VL-8B、单张 A40、BF16 / FlashAttention 2、1,024 → 256 个视觉 token、α=0.5、β=2、q=0.2，完整 5,349 题。

| 设置 | DocVQA ANLS | 差值 |
|---|---:|---:|
| 论文 EADP 数值参考 | 62.8000 | — |
| 本机 EADP，DeepStack 关闭 | 61.1660 | — |
| 本机 EADP，DeepStack 开启 | **67.9031** | 较本机关闭 **+6.7371 点** |

在 5,349 题的本机配对中，**2,446 题**回答文字改变；逐题 ANLS 有 **1,129 题提高、480 题降低、3,740 题不变**。两侧各有 4 题达到 2,048 个新 token 上限且没有 EOS，均保留在完整分母中。

后续对开启版重跑全量数据时，5,349 题的实际选择位置、输出 token 和回答均与之前的开启版一致；作者评分和独立评分逐题一致。开启版比论文数值高 5.1031 点，但论文完整配方未知，**不能把它表述为已公平超越论文，或新的剪枝算法创新**。

### 6.3 耗时和显存

开启版对完整 5,349 题进行自然生成的结果：

| 性能指标 | 本机实测 |
|---|---:|
| 平均耗时 | 0.705 秒/题 |
| 中位耗时 | 0.586 秒/题 |
| 95% 题目的耗时不超过 | 0.958 秒/题 |
| 平均吞吐量 | 1.418 题/秒 |
| PyTorch 已分配显存峰值最大值 | 约 16.70 GiB |
| PyTorch 已预留显存峰值最大值 | 约 16.83 GiB |
| 模型加载时间 | 52.917 秒，单独统计 |

总时间包括图片读取、预处理、视觉编码、EADP 选择、生成和解码；显存包含模型常驻部分，不等于所有设备进程的显存总量。输出长度不同会影响耗时。

为做等长度对照，另取 16 题，每题开启 / 关闭各一次并固定生成 32 个 token：关闭 **1.873 秒/题**，开启 **1.877 秒/题**，平均相差约 **4 毫秒/题**；两侧整次推理 PyTorch 已分配显存峰值均值均约 **16.54 GiB**。差值小于单题波动，样本不足以给出普遍固定开销；整次峰值相同也不代表不存在额外中间内存。

旧关闭版全量实验没有按本次同样口径逐题计时，因此不能拿旧运行的总墙钟时间计算严格的全量开关性能差。固定 32 token 测试与自然生成全量测试也不能直接相减。

## 七、与其他方法的对比边界

EADP 论文的 Qwen3 表格包含 DivPrune、CDPruner 和 EADP。当前公开的 Qwen3 剪枝代码中，这三种方法都没有把 DeepStack 特征传给语言模型；Qwen3 原生不剪枝路径会传递。**当前代码状态不能证明论文实际运行的代码版本，也不能确认所有对比数字由谁运行。**

现在只有 EADP 的 DeepStack 开启版做了本机全量效果和性能测试。由于设置不同，不能直接用开启版的 67.9031 与论文中其他方法的分数比较并宣布优劣。

## 八、后续计划

1. 给 EADP、DivPrune、CDPruner 使用相同的模型、数据、视觉 token 预算和 DeepStack 设置，重新进行效果比较。
2. 在相同计时口径下记录各方法的单题耗时、输出长度和显存峰值，补齐可比的效率数据。
3. 在其他任务上检验 DeepStack 的影响，并继续依据公开材料排查论文配置与评分差异。
