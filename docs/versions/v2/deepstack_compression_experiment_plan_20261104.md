## 1. 目标与本轮要回答的问题

目标是在视觉 token 压缩中获得更好的精度—真实资源曲线。以下三种结果都值得研究：

1. 精度基本保持，延迟或显存明显降低。
2. 精度明显提高，延迟只增加少量。
3. 更少资源，同时取得更好效果。

本轮不预设最后必须采用 EADP、DeepStack 新模块、token merging 或模块组合。先依次回答：

| 问题 | 对应实验 | 可以得到的结论 |
|---|---|---|
| 当前增益是否受到旧位置处理影响？ | E0、E1 | DeepStack、位置策略及二者交互的受控结果 |
| 哪几层注入有用，是否有冗余或负作用？ | E2 | 当前 checkpoint 的分层边际收益和依赖关系 |
| 正确的 token—DeepStack 对应是否重要？ | E3 | 对应关系干预的实际效果，不能直接等同于 OCR/局部像素机制 |
| 收益能否换取更少 token，实际增加了多少成本？ | E4 | 不同预算的质量—延迟—显存曲线和成本来源 |
| 其他方法真的不用吗，公平比较后谁更强？ | E5、E6 | 固定版本的代码事实与同条件本机对照 |
| 能否形成我们自己的有效方法？ | M1、M2、M3 | 通过验证门的候选，或有依据的负结果 |

优先完成 E0→E1→E4，先回答“是否值得保留、成本多少”。E2/E3定位机制；E5/E6建立竞争基线。方法探索按成本分析和机制结果分支，不把所有组合无差别全量穷举。

## 3. 共用协议：先固定样本、实现、指标

### 3.1 模型与运行

- 首轮用本机Qwen3-VL-8B同一权重快照、BF16、FlashAttention 2、batch=1、固定1024×1024输入、原始prompt与greedy生成，`max_new_tokens=2048`。将实际权重、processor、代码、环境与生成参数写入清单，不只记录模型名字。
- EADP沿用已验收的α=0.5、β=2、q=0.2；Div/CD沿用各自公开选择器，不按新结果调参。
- 位置P1是旧连续1D；P3是从未剪枝的完整图像+文本计算原生三轴位置，再按实际保留索引选取。明确decode的cache_position与rope_deltas处理，不能对压缩后的假网格重新编号。
- 文中所有由字符串/ID派生的seed均用UTF-8的SHA256前64位整数，不用Python进程随机化的内置`hash()`；序列化字段及排序固定，写入manifest。
- 原生动态分辨率与固定1024输入是两种协议。第一轮固定输入做因果控制；近期方法的作者原配置另表复现。后续若扩展动态分辨率，所有对照同步重评。
- 性能实验单张A40独占、只加载一个模型。精度生成可按显存允许并行，但不能把其耗时用于性能排名；加载模型也计入并发数量，最多两个。
- 机制实验可以复用同一图像编码与选择，以冻结干预前输入；主性能实验必须现场执行其宣称包含的图像处理、视觉编码和选择器。缓存结果只进单独的缓存工作负载表。

### 3.2 数据与样本

主诊断任务：DocVQA、TextVQA、AI2D，分别覆盖文档、场景文字和通用图示。OCRBench作为后续补充；版本、题数与评分在清单核对后冻结。

| 面板 | 规模 | 用途 |
|---|---|---|
| ANCHOR | 已有DocVQA固定16题 | 检查端点/索引/位置/输出身份，不用于筛选方法 |
| DEV | 每任务128个不同图像，每图1题，共384题 | 机制探索和有限候选筛选 |
| CONFIRM | 每任务另外256个图像，每图1题，共768题 | 第二轮独立图像筛查；允许淘汰路线，不作最终显著性依据 |
| FINAL | 各任务FULL剔除DEV、CONFIRM及其重复图像组后的所有剩余图像/问题 | 预先冻结，候选/参照锁定后仅作一次正式终验 |
| FULL | DocVQA5349、TextVQA5000、AI2D3088，实际manifest再验 | 全集描述与复现，逐任务同时报FINAL；不可称其独立于筛选集 |
| TRAIN | 官方训练集，排除所有评测图像/重复图 | 若M3成立，供teacher标注与student训练 |

先跨任务建立图像组：原始文档/页面ID、文件SHA与解码RGB尺寸+像素SHA共同检查；再用固定64-bit pHash（汉明距离≤4标记候选）审计重编码/缩放近重复，人工复核或保守合组，保存合组表及漏检限制。精确哈希不能保证排除一切语义重复。

先按`SHA256("20261104|group_id")`给全局图像组排序，再按预先固定的任务顺序DocVQA→TextVQA→AI2D选每任务DEV128组和CONFIRM256组；已分配的全局组在后续任务不可重新分配，所有跨任务成员沿用同一个split。每组每任务按`SHA256("20261104|qid")`固定一题用于面板；FULL仍保留全部问题。剩余组在任何新结果产生前冻结为FINAL，同图其他问题不能跨DEV/CONFIRM/FINAL/TRAIN。TRAIN额外做上述跨评测图排重，并在内部按图固定fit/early-stop-validation；不使用CONFIRM或FINAL做训练早停。抽样不使用答案、预测或是否改善。独立组不足时先记录缺额并冻结更小规模，不复制样本凑数。

这些验证集历史上已被本项目查看过。这里的CONFIRM/FINAL只说明其在本轮的角色，不是从未曝光的新数据。FINAL不用于本轮候选选择；正式论文还应冻结额外未用于方法选择的任务/版本或骨干评估。FULL包含开发图，必须同时报其描述结果和剔除开发图后的FINAL推断；已有全量结果重分组不会自动变成新证据。新方法训练与调参不能读取评测答案；诊断oracle仅可读取指定DEV答案并明确标记。

### 3.3 指标与判断规则

- 精度：官方逐题ANLS/TextVQA共识分/AI2D固定评分规则，并与独立实现核对。AI2D沿用可复现的固定解析，LLM judge另表披露；不按答案更换评分规则。未解析、空答、达到输出上限的题目保留在完整分母。
- 变化：每题增益、改善/退步/不变、答案变化；按任务与预先定义问题类型分层。类型可重叠，不能把它们当独立证据或用macro掩盖单任务退步。
- 统计：同题配对，按图像聚类bootstrap，确认/全量10,000次，seed=20261104。性能重采样以图像为单位并保留其重复测量，不把重复次数当独立图数。
- E2预注册三个“留一层关闭”主对比，三条主对比用98.333%聚类区间作Bonferroni控制，其他层间交互为探索性。方法候选最多3条主路线，每条只保留一个主要配置进入CONFIRM；FINAL前锁定至多一个主要候选及完整参照集合，不在CONFIRM/FINAL上挑最佳seed或有利任务。
- 精度非劣工程容忍度预设为0.5分：差值区间下界>−0.5才支持非劣；上界<−0.5支持质量不达标；介于两者为证据不足。它是本项目的取舍，不是领域通用标准。
- DEV与CONFIRM用于探索/淘汰，不能因小样本“不显著”就说等价。CONFIRM后按预定规则锁定唯一候选，再对预先冻结、与两筛查面板不重叠的FINAL作一次终验；不能把看过的CONFIRM并入FINAL区间。不实施“看到95%区间不够再补样直到显著”。正式样本量用DEV配对方差预估，若现有FINAL不足，保持未决并设计另一次独立研究；不能用包含开发图的FULL补成独立验证。

### 3.4 预设的三个成功目标

参照是在同任务、同输入协议下已复现的强基线集合。TTFT越低越好，T为候选/参照TTFT比值。DEV完成后、看CONFIRM前冻结两类参照：①质量路线对照统一K256/DS-on的EADP与DEV平均质量最高的近期可运行方法；②效率路线在已冻结的各法曲线中，对每个任务选质量距EADP K256在0.5分内且实测最快的点，无合格点则用EADP K256。其方法/预算/层数一经登记不再据CONFIRM/FINAL挑选，所有已运行对照仍完整公布。

FINAL报告候选对两个锁定参照逐任务的质量差与TTFT比，不能只展示有利的一个。质量主要比较族为3任务×2参照=6条，采用同时聚类区间或Bonferroni的99.167%区间；主要TTFT比较族同样控制6条。额外预算/模型单列复验，不从它们替换失败主比。DEV Pareto仅用于冻结参照，FINAL重新绘全部点；本章内部晋级门不自动等于SOTA。

| 路线 | 质量要求 | 资源要求 |
|---|---|---|
| 高效率 | 三个主任务均支持上述0.5分非劣 | median TTFT点估计至少降低15%，调整后比值区间上界<0.90；P95比值上界≤1.10；总显存不增加超过5% |
| 高精度、略慢 | 至少两个主任务提升≥1分且调整后区间下界>0，其余任务支持非劣 | TTFT调整后比值区间上界≤1.10，总显存≤1.05倍 |
| 更少资源、更高质量 | 达到高精度要求 | TTFT点估计降低≥10%且区间上界<1，显存不更高；若声称省显存，再单独给显存下降证据 |

这些是提前指定的研究晋级目标，不承诺实验一定达到。总显存受权重主导，还应单列视觉激活与KV字节，避免把更少token直接写成更少总显存。没有满足这些门不等于整个研究方向无价值；报告具体是哪项取舍失败。

## 4. E0：先证明实验入口正确

问题：在不剪枝时，恢复后的入口是否与原生模型一致？这是后续定位DS与位置影响的前提。

1. 在ANCHOR上运行stock原生FULL与适配入口K1024/DS111/P3，共32次自然生成；同实例对比视觉主特征、三路DS、prefill embedding/mask、三轴位置、首步logits和生成token。
2. 每题额外走一条固定教师强制前缀，至少核32个decode步的position/cache/rope；自由生成一旦分叉，不把其后的不同token轨迹误当相同输入比较。
3. 在K256上检查真实原空间ID、排序和主特征/三路DS的对应，文本区完整保留；视觉mask恰好256个，cache长度与非视觉部分正确。
4. 另核DS000“完全不传入”与分层消融的“固定槽位置零”端点，共32次自然生成；不缩短DS列表，以免把第二路误送进第一层。

**门**：选择/输入ID/索引必须完全一致；同实现无操作路径按字节核验；不同kernel的浮点容差在看准确率前预设并保存，logits误差、argmax和输出身份全部报告。失败先定位入口，不进入大样本。不能看到精度更高就把不等价当作通过。K256的稀疏原坐标是剪枝适配，不称其等于未修改的原生模型。

## 5. E1：位置策略×DeepStack的完整2×2

在同一适配实现、同一模型和每题同一EADP K256集合上，只改变两因素：

| arm | 位置 | DS注入 |
|---|---|---|
| P1-D0 | 旧连续1D | 000 |
| P1-D1 | 旧连续1D | 111 |
| P3-D0 | 原始三轴位置 | 000 |
| P3-D1 | 原始三轴位置 | 111 |

DEV 384题×4臂=1,536次自然生成。旧全量用于端点身份检查，只有完整recipe和逐题token可闭合时才复用相同记录；否则新四臂配对，不能拿历史不同引擎拼2×2。

报告两个位置策略下的DS效应、两个DS条件下的位置效应，以及差中差`(P3-D1−P3-D0)−(P1-D1−P1-D0)`。每个位置条件内off/on的主视觉、文本、初始位置和生成配置一致，DS在选择完成后干预。

**判断**：P3若未提高，仍报告结果，不按分数选1D并称其原生；若交互明显，后续DS机制限定在P3，旧增益不得直接外推。E0失败时不能靠E1分数挑“正确实现”。

## 6. E2：三层分别贡献多少，是否可以只保留一部分？

固定P3、K256和实际选择。三个二进制位表示模型配置中按顺序对应的三个LLM注入槽，不能与ViT取特征层编号混淆；运行时记录两套编号。

| arm | 三路注入开关 |
|---|---|
| D000 | 000 |
| D100、D010、D001 | 分别只保留一路 |
| D110、D101、D011 | 分别关闭一路 |
| D111 | 全部保留 |

共8臂；P3端点从E1原样复用，新6臂×384=2,304次。主对比为D111分别减去D011/D101/D110，另报单路作用与完整三因素交互。所有臂仍产生完整DS，关闭路用相同dtype零张量占槽；这是效果干预，不声称节约DS生成成本。D000的零注入须先过E0。

**判断**：若某子集在CONFIRM有保持质量的信号，且E4证实真正跳过对应计算可能带来足够成本收益，才进入部署优化；正式非劣以FINAL为准。若几层均不可删，保留全DS，转向主token压缩。这里的留一层效应以其他两层开启为条件，不是独立层贡献。某一路单独无效不说明它在其他路存在时也无效；这是对已训练checkpoint的推理消融，不推断训练时该架构可以删除。

## 7. E3：收益是否依赖正确的逐token对应？

固定P3/K256/同一选择/同一层数，四臂：

| arm | 实际送入的DS |
|---|---|
| OFF | 全关闭，复用D000 |
| MATCH | 按同一真实保留位置对应，复用D111 |
| PERM | 在保留的256行内做固定无不动点置换，三层使用同一置换 |
| MEAN | 每层对该256行求均值，再向同256行重复注入 |

置换由字符串`20261104|image_hash|perm`的SHA256前64位seed确定，不看问题答案；记录实际置换、multiset及每层范数摘要。新PERM/MEAN各384题，共768次；若PERM对比有信号，CONFIRM预先固定3个置换seed，报告全部，不能挑一个seed。

**解释边界**：MATCH优于PERM支持正确对应在这一干预下有用；不能单独证明模型恢复了局部OCR、某个像素或多尺度细节，因为ViT特征已经全局混合，错配也破坏语义相容性。MEAN还改变特征分布与局部变化强度，只是诊断控制；PERM/MEAN仍优于OFF也不证明“对齐不重要”。所有结论以逐题准确率为主，隐藏态变化与可视化仅作诊断。

## 8. E4：预算—质量—真实成本，明确优势和劣势

### E4-A：预算曲线

固定P3，EADP分别在K={128,256,512,1024}下重新执行其原选择器，每个K配DS000/111，共8臂。K1024是全视觉输入对照，不冒称论文注册剪枝配置。E1的K256端点复用，其余6臂×384=2,304次。只在E0通过后计入曲线。

预注册比较：`K128/DS111`对`K256/DS000`、`K256/DS111`对`K512/DS000`，检查DS是否能换取更少主token。它们只解释相对旧DS-off路径的收益，不能作为新方法战胜强基线的证据。真正晋级必须再对比相同实测成本附近的DS-on强基线，报告整条曲线。

### E4-B：拆开“没有注入”和“没有计算”

在K256、固定输入和选择下测四种实现，精度干预与性能优化分开：

| mode | ViT主干 | DS merger | LLM注入 | 用途 |
|---|---|---|---|---|
| C-ON | 完整 | 三路完整计算 | 三路对应注入 | 强基线 |
| C-DROP | 完整 | 三路完整计算 | 全关闭 | 隔离注入成本；与已有DS-off路径核对 |
| C-SKIP | 完整 | 跳过DS专用merger/输出分支 | 全关闭 | 测DS生成本身的额外成本 |
| C-PARTIAL | 完整 | 只计算保留层/位置需要的行 | 相应位置注入 | 仅在E2/M2质量成立且实现通过核验后测 |

C-SKIP不得跳过主视觉流需要的ViT层。验证C-SKIP与C-DROP主视觉特征和答案一致；否则是新的模型变更，不能把差值全部归于DS开销。只把特征算出后乘零属于C-DROP，不属于省算力。

### E4-C：测量协议

- 每个性能配置/任务/输出长度协议先10题预热；每任务固定64个图像、每图5次，合计192图×5=960次/配置/长度协议，按图像分块随机交错配置并记录顺序。E4阶段从DEV取图，只作成本诊断；FINAL候选锁定后从FINAL另外冻结每任务64图复测，才能用于§3.4的逐任务性能区间。另用32图×20次做DS merger/注入/selector微基准，不能拿微基准当端到端。
- 主表同时报自然生成端到端及输出token数；另报固定32个新token的长度控制实验。强制长度实验不评分，其文本也不冒充正常答案。
- T0从图片读取/预处理前开始，分别报告CPU预处理、视觉编码、DS merger/收集、选择器、LLM prefill、首token和decode。主TTFT含真正首token选择；首步logits就绪时间另列，不混用口径。
- 主计时只在边界同步，细粒度CUDA profiler单独跑，避免observer、hash、张量clone、逐层同步污染主性能。记录allocated/reserved峰值、NVML进程显存、KV缓存字节，配置之间用独立进程测显存以减少allocator历史污染。
- 主表分batch=1与预先固定的batch=4；batch4若任一算法OOM，照实报告，并另测各方法可承受的最大batch，不能用不同batch的吞吐假装同设置比较。首轮只跑batch1，候选晋级再跑batch4。
- 模型加载、文件冷缓存与热缓存分别披露；精度数据和性能数据使用相同recipe。任何性能优化必须重新核对输出或明确其数值路径差异。

自然生成与固定32token各自完整测量。初始C-ON/C-DROP/C-SKIP三配置最多3×960×2=5,760次计时生成（自然2,880、固定长度2,880），预热另计；它们不包含在第一轮6,976次精度生成里。后续C-PARTIAL、强基线或训练seed每新增一配置再计1,920次计时生成，先由实际smoke时长核准阶段预算。

**判断**：给出DS增加的绝对ms、相对TTFT、显存、长答案尾部影响和任务精度。若DS专用计算只占很小比例，先用实测分项估计优化空间，停止把该分项作为主要加速卖点；该估计不是跨kernel/设备的严格性能上界。若某任务明显退步，报告具体范围，不因DocVQA提高而隐藏。

## 10. E6：近期强方法的公平重评

基础组：原生FULL、EADP、DivPrune、CDPruner；另加固定随机选择（3个seed，全部报告）。近期组优先PriorTR，再Hi-Lo（通过E5后）。剪枝方法先DEV最终K256，不立即扩全部预算/任务全量；原生FULL始终K1024，不归入K256方法。层内方法同时报每层实际token数。

1. 原作者可运行默认配置先保留，便于核对实现和论文设置；报告复现失败及缺失工件。
2. 统一固定输入/权重/评分后比较DS-on与正确位置。不能为了使用同一wrapper而删除别人的层内融合、探针或本来存在的多层机制。需要单独官方环境时保留版本与后端差异，再做必要一致性诊断。
3. 记录每层token数、剪枝位置、merge、探针、额外前向及KV；两个方法最终都是256token，不代表总计算量相等。有意改变输入的算法在keep-all时也未必等于原生；另列“方法开启但不剪枝”消融，不能强行改掉其机制来过身份门。
4. 用DEV生成实测精度—TTFT曲线，选有限非支配参考进入CONFIRM，再扩FULL。完整比较不引用外文论文数字补空，本机分数必须有真实完整输出；论文reported另表。

## 11. M1：性能方向——保持选择的facility加速

**假设**：如果E4显示选择器是可观瓶颈，保持EADP选点不变也能获得有价值的端到端节省。

- 在DEV中固定128图的真实importance/similarity，K128/256/512，比较原作者greedy与一个优化实现，合计384个真实选择case；补重复特征、并列、零权重和边界K的合成case。
- 保留每一步argmax和tie规则，核有序选择、空间集合、输入序列及生成输出。数学上使用相同目标不保证低精度实现的选择完全一致；任一差异先作为不同近似方法单列，不能声称无损。
- 优化可从减少CPU↔GPU同步、减少kernel launch和等价lazy/batch计算着手；已有lazy greedy不是新的学术创新。最多两种实现，避免无目标工程搜索。
- 先微基准，再按E4端到端测量。候选晋级门：selector中位至少快2倍、真实TTFT至少快10%，输出身份通过；CONFIRM仅筛选，最终能否达到§3.4高效率目标由FINAL决定。若selector很快但端到端达不到目标，终止该实现作为主论文方向，工程收益仍保留。

产物：逐步选择差异为0的实际范围、性能区间、输入规模/预算适用范围；不得把有限测试称成所有输入的形式化等价证明。

## 12. M2：联合分配主token与DeepStack计算

**假设**：主token数与各层DS信息不必固定等比例，可在同一真实成本下取得更好效果。只有E2/E4表明有质量冗余和可观可削减成本时才运行。

第一步固定主K256，用总DS行预算384，对照完整三路768行：

| 配置 | 三层实际注入行数 |
|---|---|
| ALL | [256,256,256] |
| BALANCED | [128,128,128] |
| EARLY | [192,128,64] |
| LATE | [64,128,192] |

每个384预算配置各用两种预定选择：原EADP完整贪心顺序的嵌套前缀、按同一固定seed产生的共同随机排列的嵌套前缀。三层共享各自策略的同一排列，行数改变时取前b行；记录层间交集。主256位置保持不变，DS选中子集以外注入零；三种分配×两策略=6个新DEV臂，ALL复用。进入CONFIRM时随机策略增加预定3个seed并全部报告。EARLY/LATE同时改变层位预算与实际行集，其差不能单独归因层的重要性；E2提供另一个条件消融。该阶段先回答“能删什么”，不能声称省了计算。

仅将DEV最有希望的一种分配实现为真实稀疏计算。关键时序：EADP的保留位置必须等最终主视觉特征产生后才知道，而三路DS在视觉塔中途产生。因此先暂存三个DS merger之前的中间hidden、patch分组/排列和dtype；最终主特征与EADP选点完成后，再按原4-patch组gather，延迟执行各路merger并scatter。计入三个中间hidden的驻留、复制/搬运、gather与延迟执行成本，不能预先使用尚未产生的EADP选择，也不能只报省下的GEMM时间。

先证明该merger在此维度上可独立计算，保持归一化、空间重排与主序列位置；不能假设任意层提前gather等价。对比“原时序全算后遮零”与“暂存后少算再scatter”，在看精度前冻结数值容差；若生成不一致，明确数值路径变体并重评。若暂存成本抵消收益，M2即未达到性能目标。

第二步仅在第一步过门后，将该唯一配置与E4最接近成本的完整DS小K/大K比较；主K与DS行预算都报出，不把DS行数当LLM序列长度。若固定分配已改善，再考虑可由图像/问题预测的forward-only预算控制器，训练只用TRAIN，和同平均成本的固定分配、随机分配对照。动态预算要报告均值/P95/最大预算及真实成本分布，不能靠少数大预算题提高分数却只报均值token。

**停止门**：质量差的区间上界<−0.5支持该配置不达标；区间跨门槛为未决，不可称存在冗余，最多按冻结规则在独立面板继续筛查。只有质量已支持非劣、但实测可削减成本明确不足时，才可说“存在可删余地，但当前实现经济性不足”，不训练控制器或无条件扩全量。若成本测量也很不确定，先补独立性能样本而不提前断言。单纯恢复DS不是M2贡献。

## 13. M3：精度方向——先检验漏选信息，再训练可部署utility

**假设**：在保留原生DS和位置后，仍有少量漏选位置能改善答案，且这种效用能由forward特征预测。历史teacher/student结果不能直接证明它在新路径下成立。

先做有界oracle：从DEV按已有hash顺序固定DocVQA64图、TextVQA32图、AI2D32图，总128图；只覆盖两个文字任务与AI2D的有限样本，不外推一般任务。固定K256与r={8,16}，明确允许该诊断读取这128图的DEV参考答案。先缓存原EADP有序集合S，删除位置永远为其最后r个贪心入选ID，不根据答案改变删除规则。

候选来源与8个提案定义如下；所有候选真实主特征、三路DS和P3位置同步替换，主序列仍为256行：

1. 在不剪枝K1024/DS111/P3上，冻结所有模型权重，只对四个视觉特征流的叶tensor求一次参考答案平均NLL的输入梯度；固定使用canonical列表第一条参考答案（不按loss选参考），teacher答案最多128token，截断比例单列。该backward仅为离线诊断，内存/成本如实记录。
2. 主流分数定义为`u0(i)=mean_d(abs(V_i[d]*grad_V_i[d]))`；每路DS同样计算`us(i)`。每路在本图1024位置作0–1百分位rank、tie取原ID；MAIN使用主流rank，MULTI使用四路rank的算术平均。这个多流rank只是固定oracle提案规则，不预设为部署创新或最优融合。
3. 每来源在落选位置中取其分数最高的64个为提案池；RANDOM从全部落选位置用固定seed均匀取64个。各自按`seed=hash(20261104,qid,source,r,j)`生成8组**不放回**的r元素子集；提案0取池内分数前r个，RANDOM的提案0取其随机排列前r个，后7组为池内均匀r子集。池内排序tie为ID，重复子集按同一确定规则重抽，最多128次；若不足8个唯一集合，三来源该题同时降为可获得的最小提案数并记录，不给某一来源更多teacher调用。
4. 每来源每个r都比较相同的do-nothing S与8个替换提案，按teacher-forced NLL最小选1个，tie优先do-nothing、再按提案号。随机控制也用答案在同数提案中选最佳；不能让新策略有更多答案搜索预算。相同S的loss可跨来源缓存，逐题记录实际forward数。
5. MAIN/MULTI/RANDOM×两个r共6个获胜集合各自然生成一次，原EADP输出复用；每题新增最多6次，共768次自然生成。teacher最多为每题1个全图输入梯度backward、1个原S forward、6×8个提案forward；缓存重复输入会减少实际调用，所有来源按相同规则缓存。三方法共享相同梯度提取前向，不把它当推理免费信息。

128图的teacher上限为128次全图梯度前向及backward、6,272次额外teacher-forcing前向，加768次自然生成；与学生训练/部署成本分开。若显存不足，保留OOM与实际batch，允许另冻离线checkpoint/offload方案，但不能悄悄改变teacher输入/答案或称原方案完成。

oracle用答案选集合，只测这一有界搜索的空间，不是理论上界，不进入部署排名，也不证明DS是收益的因果来源。这128图永远不用于学生确认。主要比较为MULTI相对MAIN和同预算RANDOM的真实生成增益；若区间已排除预设1分最小增量，停止多流候选定义；若区间宽则未决，可按预定规则另在剩余DEV执行同协议，结果分批报告，不能改提案规则追分或把两次查看当一次正式检验。

有明确空间后，才在TRAIN内部按图80% fit/20% early-stop-validation标注/训练一个轻量utility predictor；CONFIRM/FINAL不参与训练、早停或seed选择，全部推理forward-only。问题条件q固定为原LLM问题文本embedding的非padding平均（只含问题，不含答案）；每个视觉流与q各layer-normalize并投影到64维，拼接后用320→128→64→1的GELU MLP打分。MULTI输入四路V/Z0/Z1/Z2，容量控制MAIN重复输入V四次，保持同样维度/参数量/q及更新次数；另列简单均值/范数和原EADP。此定义用于保证条件与容量可比，不预设其优于已有学生。

两个student使用同一份teacher排序监督，训练seed={0,1,2}全部报告。在TRAIN内部validation上按冻结的teacher排序loss选唯一主部署checkpoint，tie取较小seed；在看CONFIRM前完成选择。正式6条主比较只用该checkpoint，其余seed是完整附列的训练稳健性检查，不选CONFIRM/FINAL上最好的seed，不把三seed平均当一个免费ensemble。具体tokenizer/teacher标签/损失/训练量在TRAIN实际可用性与teacher成本检查后另冻`training_plan.json`，不以本段宣称学生入口已实现。先比较Top-K与facility各一种，最终selector由DEV质量/真实成本决定。

旧L4 student若重用，必须补计全token早层前向与prefix/KV复用成本，并说明新的DS/位置/监督变化足以重新检验，不原样重复失败配置。学生是否有足够信息恢复teacher收益与teacher是否强分开验证。

**晋级门**：CONFIRM仅用于路线筛选；锁定候选后在FINAL按§3.4作正式终验。oracle有效但student无效，结论为效用不可被当前廉价predictor恢复；不能拿oracle作可部署贡献。集合条件救回已有[CoRePrune](https://arxiv.org/abs/2609.26484)等先行工作，M3现在是机制筛选，部署版须在可用信息、监督或计算代价上证明具体区别，多流简单打分本身也不能预定为创新。

- M1仅在selector占比支持时做；M2仅在可删DS成本支持时做；M3仅在oracle支持时训练。按各章有限矩阵执行，不取三路线的笛卡尔积。
- 同时保留最多3条候选；每条最多一个主要配置进入CONFIRM。先预注册主要对比和显存/延迟门，再解锁768题结果；这一轮结果只作探索性筛查。按§3.4预设效用目标选择至多一个主要候选，与两个预先冻结参照进入FINAL；此后不修改候选。CONFIRM不并入正式终验区间。
- 多问缓存是可选系统工作负载，不混入单图单问SOTA：先核可用问题数，Q={1,2,4}，固定100张至少4问的图；Q=8只能用另有足够问题的子集。强对照必须同样缓存完整视觉特征，并计首题建缓存/每题选择/显存，禁止看未来问题或答案。

### 第三轮：完整确认与泛化

先在DocVQA对锁定候选与两个锁定参照完整生成FULL：非训练候选最多3×5,349=16,047次；若M3保留3个训练seed，则是3个候选实例+2参照=5×5,349=26,745次，不能仍按一个checkpoint报成本。正式推断仅使用预先划出的FINAL；FULL主表同时显示其包含开发样本。M3按预定方式报告每seed与跨seed均值/范围，seed间差异不可只用题目bootstrap代替。

若DocVQA主比明确失败可停止，不因为提前查看一项就宣布三任务成功；未决保持未决。继续时，相同锁定配置扩TextVQA FULL与AI2D FULL：非训练候选新增3×(5,000+3,088)=24,264次，三seed训练候选新增5×(5,000+3,088)=40,440次。正式推断同样仅用各自FINAL并控制预设6条主要方法比较；训练seed各自结果完整附列，不从中挑有利对比。旧记录只有完整相同协议可复用，新位置协议不能抄旧分。

主结果成立后再扩K128/512，先DEV曲线再决定是否进行另一项预注册复验；另一骨干或未用于选择的任务作额外泛化。若在FINAL失败后重新设计方法，该FINAL已经成为开发证据，必须另设独立终验，不能重复使用它宣称确认。最终发布完整有记录的所有主对比，不按任务取历史最佳格。SOTA只在已验证模型/任务/资源约束下表述，不因超过EADP一项就声称整个VLM压缩领域第一。

## 15. 每轮必须交付什么

输出根目录建议`reproduction/20261104/deepstack_compression/`，各实验使用独立子目录；当前该目录和新runner不因此文被假定已经存在。

| 文件 | 必含内容 |
|---|---|
| `plan.json` / `manifest.jsonl` | 版本、权重/源码/输入SHA、样本用途、arm、预算、seed、预设对比和停止门 |
| `observations.jsonl` / `raw_predictions.jsonl` | 原qid/图像、真实选择与排序、各层DS注入数量/摘要、位置/cache摘要、生成tokens、原回答、EOS/截断 |
| `performance.jsonl` | 计时边界、预热/重复/顺序、同步、输出长度、各层token、allocated/reserved/NVML/KV、并发状态 |
| `verification.json` / `terminal.json` | 完整题数、输出解码、索引/端点、源码身份及原worker/容器真实退出；失败记录保留 |
| `scores.jsonl` / `analysis.json` | 官方与独立逐题分、配对差/退步、聚类区间、全部seed、阶段结论 |
| `RESULT.md` | 问题、干预、结果、成本、失败/未决/继续理由与边界 |

只在诊断锚点保存完整高维数组；全量可保留哈希/摘要但明确无法事后重建原tensor。性能主跑避免保存高开销中间数组。当前可复用的是旧三方法driver/observer/验证与作者评分思路；新的mRoPE、分层、稀疏merger和计时入口仍需实现及核验。文档不提供伪装成现成可运行的CLI。

最终先生成两张核心图：每方法/预算的精度—TTFT散点与Pareto曲线，以及精度—实际KV/峰值显存曲线；附DS层边际图、质量救回/退步表和成本堆叠图。问题类型、置换控制与案例只解释现象，不代替主对比。

## 16. 结果出来后如何决定方向

| 观察到的结果 | 下一步 |
|---|---|
| DS收益稳定、成本很小 | 三方法统一保留DS；主精力转向主token效用和selector成本 |
| 部分DS可删且确实省时 | 进入M2，比较固定与可预测分配，不盲目训练 |
| DS收益强依赖正确对应 | 把逐token对齐作为硬约束；进一步研究需新的控制，不能直接宣布OCR机制 |
| 位置修复改变DS效应/方法排名 | 在正确位置协议下重建主表，旧表保留为诊断 |
| selector是主要可优化成本 | 先M1，用同输出的真实速度收益决定是否值得继续 |
| oracle有空间、forward predictor恢复不了 | 改监督或表示；报告学生失败，不把oracle称新方法 |
| 仅在DS-off或更大预算下赢 | 不满足主比较目标，继续定位或停止该配置 |
| 未达到门且区间很宽 | 明确未决；DEV诊断可按冻结规则另批补充，FINAL一次终验后需新独立研究；不宣布无效或等价 |
