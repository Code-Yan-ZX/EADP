# EADP 开启 DeepStack 实验汇报

> 本文件聚焦 DeepStack。包含此前论文复现、全部对照结果和排查过程的汇总见 [EADP 复现与 DeepStack 实验汇报](eadp_v2_reproduction_report_20261103.md)。

汇报日期：2026 年 11 月 3 日  
实验模型：Qwen3-VL-8B  
实验数据：DocVQA 验证集，5,349 道题

## 一、本次结论

在本机 DocVQA 全量实验中，将 DeepStack 特征接入 EADP 的语言模型输入后，ANLS 得分从 **61.1660 提高到 67.9031**，提升 **6.7371 个百分点**。

在 16 题的小样本速度对照中，开启后的平均耗时仅比关闭时多约 **4 毫秒/题**；这一差值小于单题测量波动。开启版随后完成了 5,349 题的性能记录：平均 **0.705 秒/题**，本次测到的 PyTorch 显存分配峰值最高约 **16.70 GiB**。

目前可以认为：在这台机器和这一模型配置下，保留 DeepStack 有明显的 DocVQA 效果收益，小样本中没有观察到明显的额外耗时。是否对其他数据集和其他剪枝方法也成立，还需要进一步实验。

## 二、实验背景

EADP 通过剪掉部分视觉 token，减少大模型需要处理的视觉信息量。本次实验中，视觉编码器输出 **1,024 个视觉 token**，EADP 从中保留 **256 个**，再交给语言模型处理。

Qwen3-VL 的 DeepStack 会向语言模型传递视觉编码器中多层的视觉特征，帮助模型利用不同层次的图像信息。检查作者公开的 Qwen3 剪枝代码时发现：虽然视觉编码器产生了 DeepStack 特征，但 EADP 的公开剪枝路径没有将这些特征继续传入语言模型。

因此，本次保持 EADP 原有的 token 选择方式，在选出的 256 个位置上，将对应的 DeepStack 特征补充传入语言模型，并与关闭时进行对照。该设置是在公开实现上进行的修改，**不能认定是作者论文主表实际使用的配置，也不能把开启模型原有功能称为新的剪枝算法**。

## 三、实验设置

| 项目 | 设置 |
|---|---|
| 模型 | Qwen3-VL-8B |
| 数据集 | DocVQA 验证集，5,349 题 |
| 硬件 | 单张 NVIDIA A40 |
| 视觉 token 数量 | 1,024 → 256 |
| 图像输入尺寸 | 1,024 × 1,024 |
| 精度与注意力实现 | BF16、FlashAttention 2 |
| EADP 参数 | α = 0.5，β = 2，q = 0.2 |
| 评价指标 | ANLS，数值越高表示回答与参考答案越接近 |

效果对照使用同一个模型实例、同一批题目和相同的 EADP 选择方式；开启时，DeepStack 特征按该题实际选中的视觉 token 位置传入。

## 四、效果结果

| 来源及设置 | DocVQA ANLS | 与本机关闭版的差值 |
|---|---:|---:|
| EADP 论文报告值 | 62.8000 | 作为论文参考 |
| 本机 EADP，DeepStack 关闭 | 61.1660 | — |
| 本机 EADP，DeepStack 开启 | **67.9031** | **+6.7371 点** |

论文值来自 [EADP 论文表 4](https://arxiv.org/html/2607.02484v1#S5.T4)。本机关闭版与论文相差 **−1.6340 点**；开启版比论文数值高 **5.1031 点**，但由于论文的完整运行配置未确认，这只是数值参考，不能据此声称完全复现或公平超越论文方法。

在本机同实例开关对照中，5,349 题里有 **2,446 题**的回答文字发生变化；按逐题 ANLS 计算，**1,129 题提高、480 题降低、3,740 题不变**。后续对开启版重新运行全量数据时，选中的视觉位置、生成 token 和回答均与之前的开启版逐题一致；作者评分与独立评分也一致。

## 五、性能结果

### 5.1 开启版的全量性能

以下为 DeepStack 开启、自然生成答案时的 5,349 题本机实测：

| 指标 | 结果 |
|---|---:|
| 平均耗时 | 0.705 秒/题 |
| 中位耗时 | 0.586 秒/题 |
| 95% 的题目耗时不超过 | 0.958 秒/题 |
| 平均吞吐量 | 1.418 题/秒 |
| PyTorch 已分配显存峰值的最大值 | 约 16.70 GiB |
| PyTorch 已预留显存峰值的最大值 | 约 16.83 GiB |
| 模型加载时间 | 52.917 秒 |

单题耗时包含图片读取、预处理、视觉编码、EADP 选择、答案生成和解码；模型加载单独统计。显存数字包含模型本身，是 PyTorch 分配器的统计值，并不等于整张显卡上所有进程的显存总占用。自然生成的回答长度不同，会影响每题耗时；4 题达到 2,048 个生成 token 的上限，仍保留在全量统计中。

### 5.2 DeepStack 开关的小样本性能对照

为了让两侧的生成长度一致，另外选取 **16 道题**，让开启和关闭两侧都固定生成 **32 个 token**：

| 指标 | DeepStack 关闭 | DeepStack 开启 | 差值 |
|---|---:|---:|---:|
| 平均总耗时 | 1.873 秒/题 | 1.877 秒/题 | 开启约多 4 毫秒/题 |
| PyTorch 已分配显存峰值均值 | 约 16.54 GiB | 约 16.54 GiB | 本次未测出差异 |

该对照每题每侧仅测量一次，4 毫秒小于单题测量波动，不能当成所有设备上的固定开销。整次推理显存峰值未变化，也不意味着 DeepStack 完全没有额外中间内存。固定输出 32 个 token 与上面全量实验的自然生成长度不同，**两张表中的单题耗时不能直接相减**。

之前的关闭版全量实验没有按这次相同的方式逐题计时，因此目前没有严格可比的全量开关速度差。

## 六、与其他剪枝方法的关系

EADP 论文的 Qwen3-VL 对比表包含 DivPrune 和 CDPruner。检查作者目前公开的 Qwen3 代码发现，**DivPrune、CDPruner 和 EADP 的剪枝路径都没有把 DeepStack 特征传给语言模型**；Qwen3 原始不剪枝路径则会传递。这个判断针对公开代码，不能证明论文每个表格数字实际使用的代码版本和运行参数。

目前我们只对 **EADP 开启 DeepStack** 跑了全量实验。由于 DeepStack 设置不同，不能直接把开启后的 67.9031 与论文中其他剪枝方法的数字比较，并据此判断方法优劣。

## 七、下一步

1. 在相同模型、数据集、视觉 token 数量和 DeepStack 设置下，分别测试 EADP、DivPrune 和 CDPruner 的效果。
2. 使用同一计时方式，记录各方法的平均耗时、耗时分布、显存峰值和输出长度，建立公平的性能对照。
3. 在更多任务上验证 DeepStack 的收益，判断 DocVQA 上的结果能否推广。
